1한눈에 보기

  • 칸별 오류: 검사기가 "무엇이 틀렸나"뿐 아니라 "어느 칸인가"(Field)도 돌려준다. 화면은 그 칸 아래에 빨간 글자를 보이고 커서를 옮긴다. 토스트는 쓰지 않는다.
  • 서버 새 규칙 반영: 직접 연결(TCP_DIY)에서 IP를 비우면 서버가 "앱이 접속한 서버 주소"를 기기에 알려 준다. 그 주소가 집 안(사설) IPv4가 아니면 서버가 400으로 거절하므로, 앱이 보내기 전에 먼저 막는다.
  • Wi-Fi가 설정되지 않았으면 입력 전에 빨간 카드 + "설정으로" 버튼을 보인다.

2흐름 그림 — "등록 시작"을 누르면

3코드 해설

① 결과에 "어느 칸"을 담는다

전
static Result fail(String error) {
    return new Result(error, null);
}
후
public enum Field { NAME, PAYLOAD, WIFI, TYPE }

static Result fail(Field field, String error) {
    return new Result(error, field, null);
}
무엇을 실패 결과가 문구와 함께 칸 이름을 갖는다.
왜 화면이 문구를 보고 칸을 추측하지 않아도 된다. 규칙은 검사기 한 곳에만 있다.
빼면 예전처럼 토스트 한 줄만 뜨고, 사용자는 어느 칸을 고쳐야 할지 찾아야 한다.

② IP를 비웠을 때 서버 주소 검사

if (ip.isEmpty()) {
    if (serverHost != null && !isLanIpv4(serverHost.trim())) {
        return Result.fail(Field.PAYLOAD, "지금 서버 주소가 집 안 IP가 아니라 …");
    }
    return Result.ok("");
}
무엇을 빈 IP는 "지금 서버 주소를 써 달라"는 뜻이다. 그 주소가 10.x, 172.16~31.x, 192.168.x, 169.254.x가 아니면 막는다.
왜 기기는 집 Wi-Fi 안에서 서버에 접속해야 하므로 서버도 같은 범위만 받는다. 서버 오류 문구는 "요청 형식이 올바르지 않습니다" 하나라서, 앱이 미리 이유를 알려 주는 편이 친절하다.
빼면 이름을 myserver.local로 적어 둔 사람은 "요청 형식" 오류만 보고 원인을 알기 어렵다.

③ 오류를 칸에 붙이기

switch (result.field) {
    case NAME:    layoutName.setError(result.error); editName.requestFocus(); break;
    case PAYLOAD: (isMatter() ? layoutCode : layoutServerIp).setError(result.error); break;
    default:      showFormError(result.error); break;   // Wi-Fi 등 칸이 없는 오류
}
무엇을 TextInputLayout.setError는 칸 테두리를 빨갛게 하고 아래에 문구를 붙인다. 글자를 고치면 TextWatcher가 오류를 지운다.
왜 같은 PAYLOAD라도 Matter면 코드 칸, 직접 연결이면 IP 칸이다. 이 구분은 화면만 안다.

4용어 풀이

  • TextInputLayout: 입력칸을 감싸 힌트·도움말·오류·글자 수를 보여 주는 Material 부품.
  • MaterialButtonToggleGroup: 버튼 여러 개 중 하나만 눌리게 하는 묶음. 여기서는 Matter / 직접 연결.
  • 사설 IPv4: 집·회사 안에서만 쓰는 주소 범위(10/8, 172.16/12, 192.168/16). 169.254/16은 공유기 없이 자동으로 정해지는 주소.
  • 뒤로 스택: addToBackStack으로 쌓은 화면. 뒤로 가기를 누르면 직전 화면으로 돌아간다.

5이해도 질문

  1. 같은 Field.PAYLOAD 오류인데 화면이 붙이는 칸이 두 개인 이유는?
  2. 서버 주소가 172.32.0.1이고 IP 칸을 비우면 어떻게 되나? 172.20.0.1이면?
  3. 5개 인자 validate(서버 주소 없음)를 남겨 둔 이유는?
정답 보기
  1. Matter는 페어링 코드, 직접 연결은 서버 IP가 payload이기 때문. 검사기는 종류와 상관없이 "payload 칸"이라고만 알려 준다.
  2. 172.32는 사설 범위(172.16~31) 밖이라 막힌다. 172.20은 통과한다.
  3. 기존 테스트와 서버 주소를 모르는 호출 쪽이 그대로 쓰도록. null이면 이 검사만 건너뛴다.

실습 1 — 이름 칸 글자 수 미리 막기

목표: 65자 이상은 아예 입력되지 않게 한다. 고칠 파일: fragment_add_device.xml. 완료 기준: 64자 뒤로 글자가 더 들어가지 않고, 카운터가 64/64에서 멈춘다.

힌트TextInputEditText에 넣는 속성 하나로 된다.
정답android:maxLength="64". 단 이 속성은 UTF-16 단위로 세서 이모지는 2개로 친다. 그래서 최종 판정은 검사기(code point 기준)가 한다.
