APP-07g-1 해설 — 타일 설정 모델과 저장

ui-1 브랜치 · UI 1차 07g · D10(항목)·D11(기본값)·D12(저장 형식) · 2026-11-24

1한눈에 보기

  • 무엇을 저장하나: 기기마다 홈 타일에 보일 항목 4개. 현재 W, 누적, 추이선(작은 선 그래프), 크기 1칸/2칸. 이름·상태 칩·스위치는 항상 보여서 설정에 없다.
  • 기본값: W 켬, 누적 켬, 추이선 끔, 1칸. 지금(07b) 타일 모양과 같아서 업데이트해도 홈이 달라지지 않는다. 결정 53 "추이선 없음"이 이 기본값이다.
  • 어디에: TilePrefs 파일, 키 tile.<deviceId>, 값은 JSON 한 줄 {"v":1,"power":true,"total":true,"trend":false,"span":1}.
  • TCP_DIY는 전력을 재지 않아 크기만 고를 수 있다. 저장값은 그대로 두고 화면에 쓸 때만 끈다(effectiveFor).
  • 이번 단계는 모델과 저장소뿐이다. 홈에 반영은 07g-2, 꾸미기 화면은 07g-4.

2흐름 그림 — 읽을 때 지키는 규칙

3코드 해설

① 항목별로 타입을 확인한다

stored = GSON.fromJson(json, Map.class);
bool(stored.get("power"), DEFAULT.power)   // Boolean이 아니면 기본값
왜 처음에는 Boolean 필드로 바로 읽었는데 테스트에서 "power":"yes"가 false로 읽혔다(Gson이 문자열을 불리언으로 바꿔 줌). 사용자가 켠 적 없는 값이 꺼짐으로 바뀌는 셈이라, Map으로 읽고 진짜 true/false일 때만 쓰도록 고쳤다.

② 값은 바꾸지 않고 새로 만든다

public TileConfig withTrend(boolean value) {
    return new TileConfig(power, total, value, span);
}
왜 꾸미기 화면(07g-4)이 미리보기와 저장에 같은 설정 객체를 쓴다. 한 곳에서 몰래 바뀌지 않도록 필드를 final로 두고, 바꿀 때는 새 객체를 만든다.

③ 파일을 순서 저장과 나눈다

public static final String PREFS_NAME = "TilePrefs";
public static String keyFor(String deviceId) { return "tile." + deviceId; }
왜 기기 하나가 키 하나라 삭제(07g-5) 때 remove 한 번이면 된다. 순서(DashboardPrefs)와 섞지 않아 둘을 따로 지우거나 옮길 수 있다.

4용어 풀이

  • 형식 버전(v): 나중에 항목이 늘어 모양이 바뀌면 숫자를 올려, 옛 값을 읽을 때 구분하려고 넣는 값.
  • 불변 객체: 만든 뒤 값이 바뀌지 않는 객체. 여러 곳이 같이 써도 안전하다.
  • SharedPreferences: 앱 전용 작은 키-값 저장 파일(XML). 앱을 지우면 함께 지워진다.

5이해도 질문

  1. {"v":1,"trend":true}를 읽으면 결과는?
  2. TCP_DIY 기기에 저장된 설정이 {"power":true,…,"span":2}이면 홈 타일에 W가 보일까?
정답 보기
  1. W 켬·누적 켬·추이선 켬·1칸. 빠진 항목만 기본값.
  2. 보이지 않는다. effectiveFor("TCP_DIY")가 W·누적·추이선을 끄고 크기(2칸)만 남긴다.

6응용 실습

실습. "상태 문구" 항목 추가 (형식 버전 올리기)

  • 목표: 설정에 meta(오프라인 "기기 응답 없음" 줄 보이기, 기본 켬)를 더한다.
  • 고칠 파일: view/TileConfig.java(필드·with·JSON), TileConfigTest
  • 완료 기준: 옛 값 {"v":1,…}을 읽으면 meta가 켬(기본값), 새로 저장하면 "v":2와 "meta"가 들어간다.
힌트빠진 항목은 기본값 규칙이 이미 있으므로 옛 값을 위한 특별한 코드는 필요 없다. FORMAT_VERSION만 올린다.
