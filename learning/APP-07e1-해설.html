ui-1 브랜치 · UI 1차 07e · UI-27·28 · 2026-11-24

1한눈에 보기

  • 칸별 오류: 설정 저장 때 토스트 한 줄 대신, 틀린 칸마다 빨간 문구를 한꺼번에 보인다(IP 형식, 포트 1~65535, 토큰 형식, Wi-Fi 길이·제어 문자). 검사는 새 순수 함수 SettingsInputValidator.
  • 401이면 토큰 칸: 서버가 토큰을 거절해 이 탭으로 왔으면 토큰 칸에 "서버가 이 토큰을 거절했어요"와 커서.
  • 첫 실행 안내 카드: 토큰이 저장된 적 없으면 맨 위에 3단계(주소 → 토큰 → 연결 테스트) 카드. 3단계 버튼은 07e-2에서 붙인다.
  • 가림·보기 눈 버튼에 TalkBack 라벨("토큰 보기", "비밀번호 보기"), SSID 칸에 2.4GHz 안내.

3코드 해설

① 오류를 하나가 아니라 모두 모은다

Map<Field, String> errors = new EnumMap<>(Field.class);
String ipError = checkIp(ip);
if (ipError != null) errors.put(Field.SERVER_IP, ipError);
...
왜 기기 추가 화면은 칸이 적어 첫 오류에서 멈췄지만, 설정은 칸이 5개라 하나 고치고 저장하고 또 고치는 반복을 줄이려고 모두 보인다. EnumMap은 enum 순서(화면 위→아래)대로 돌아서 첫 오류 칸에 커서를 놓기 쉽다.

② 토스트 → 칸 오류

전
if (ip.isEmpty() || port.isEmpty()) {
    Toast.makeText(.., "서버 IP와 포트 번호를 모두 입력해주세요.", ..).show();
    return;
}
후
if (showErrors(errors)) return;   // 칸마다 setError

③ 401을 기억했다가 보여 주기

if (RetrofitClient.hadUnauthorizedSinceSave()) {
    tilApiToken.setError("서버가 이 토큰을 거절했어요. 새 토큰을 입력해 주세요.");
}
무엇을 401 안내를 한 번만 하려고 이미 있던 "안내했음" 표시를 그대로 읽는다. 설정을 저장하면 내려간다.
빼면 탭이 바뀌어도 사용자는 토스트가 사라진 뒤 무엇이 틀렸는지 알 수 없다.

4용어 풀이

  • EnumMap: 키가 enum인 Map. 순서가 enum 선언 순서로 고정된다.
  • endIconContentDescription: 입력칸 오른쪽 아이콘(눈)의 TalkBack 이름.
  • 2.4GHz: 공유기 Wi-Fi 주파수 중 하나. 작은 IoT 기기는 대부분 이것만 지원한다.

5이해도 질문

  1. 토큰 칸이 비었는데 오류가 아닌 경우는?
  2. 포트 "65536"과 "123456"은 각각 어느 줄에서 걸리나?
정답 보기
  1. 이미 저장된 토큰이 있을 때(기존 토큰 유지).
  2. 65536은 숫자로 바꾼 뒤 범위 검사, 123456은 먼저 길이(5자리 초과) 검사에서 걸린다.
