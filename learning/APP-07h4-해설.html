APP-07h-4 해설 — 입력 검사와 제어 잠금

ui-1 브랜치 · UI 1차 보완 07h ④ · U4·U5·U20 · 2026-11-25

1한눈에 보기

  • 칸별 오류 전부(U4): 기기 추가 검사가 걸린 칸을 모두 errors(칸 → 문구)에 담는다. 화면은 모든 칸에 한 번에 보이고 첫 칸에 커서를 둔다. 예전 field·error는 첫 오류로 남겨 다른 코드는 그대로 돈다.
  • 경계 입력(U5): IPv4 자리 앞 0(192.168.01.10)과 포트 앞 0(08000), 공백만 있는 이름(전각·줄 바꿈 없는 공백 포함)을 막는다.
  • 제어 중 목록 새로고침(U20): 새 목록이 와도 진행 중인 기기는 "켜는 중…"과 잠금을 이어 받는다. 실제 상태는 기억해 두었다가 요청이 끝나면 보인다.

3코드 해설

① 첫 오류에서 멈추지 않기

before
String nameError = checkName(deviceName);
if (nameError != null) return Result.fail(NAME, nameError);
String wifiError = checkWifi(ssid, password);
if (wifiError != null) return Result.fail(WIFI, wifiError);
after
Map<Field, String> errors = new LinkedHashMap<>();
if (nameError != null) errors.put(NAME, nameError);
if (wifiError != null) errors.put(WIFI, wifiError);
errors.putAll(payloadResult.errors);
왜 이름을 고치고 누르면 그제야 코드 칸 오류가 나오는 "두더지 잡기"가 됐다. 설정 화면 검사는 이미 전부 보여 줘서 두 화면이 달랐다.
왜 LinkedHashMap 넣은 순서가 유지돼 "첫 오류"(커서를 둘 칸)가 늘 이름 → Wi-Fi → 코드 순이다.

② 앞 0 거절

if (part.length() > 1 && part.charAt(0) == '0') return false;
왜 010을 어떤 프로그램은 10, 어떤 것은 8진수 8로 읽는다. 앱이 통과시킨 주소를 서버나 기기가 다르게 읽을 수 있어 아예 받지 않는다. 0 한 자리는 그대로 된다.

③ 진행 중 표시 이어 붙이기

for (Device device : fresh) {
    if (!isPending(device.getId())) continue;
    device.setState(LOADING);
    device.setPendingCommand(old.getPendingCommand());
}
왜 목록 응답은 새 Device 객체를 만든다. pendingCommand는 앱만 아는 값(transient)이라 새 객체엔 없다.
순서 주의 remember(실제 상태 기억)를 먼저 해야 요청이 실패했을 때 목록이 알려 준 값으로 돌아간다.

4용어 풀이

  • LinkedHashMap: 넣은 순서를 기억하는 Map.
  • 전각 공백(U+3000): 한글 입력기에서 들어갈 수 있는 넓은 공백. trim()으로는 안 지워진다.
  • transient: Gson이 JSON으로 읽고 쓰지 않는 필드. 앱 안에서만 쓰는 값.

5이해도 질문

  1. 이름이 비고 코드가 12자리면 커서는 어느 칸으로 갈까?
  2. carryOver를 remember보다 먼저 부르면 무엇이 틀어질까?
정답 보기
  1. 이름 칸. 두 칸 모두 오류 문구가 뜨지만 커서는 첫 오류로.
  2. 목록의 기기 상태가 이미 LOADING으로 바뀐 뒤 기억하려 해서 remember가 무시한다(LOADING은 기억하지 않음). 실패 때 옛 값으로 돌아간다.

6응용 실습

목표: 기기 이름 앞뒤 공백을 지운 값으로 보내기. 고칠 파일: CommissionInputValidator(새 브랜치에서). 완료 기준: Result에 정리된 이름을 담고, " 거실 "을 넣으면 "거실"이 나오는 테스트 통과.

힌트payload처럼 Result에 name 필드를 더하고 ok()에 넘긴다. 서버 규칙(64자)은 지운 뒤 길이로 센다.
정답 방향String cleaned = name.strip();(Android에선 API 33 미만이면 직접 공백을 건너뛰는 반복문) → 길이 검사 → Result.ok(payload, cleaned).
