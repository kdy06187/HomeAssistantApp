APP-07c-4 해설 — 일/주/월 탭

ui-1 브랜치 · UI 1차 07c · D1(기간 고정: 일 7일·주 8주·월 6개월) · 2026-11-24

1한눈에 보기

  • 차트 카드 위에 탭 4개: 최근 · 일 · 주 · 월. "최근"은 07c-3의 원본 기록, 나머지는 서버가 합쳐 준 집계(E7 period).
  • 기간은 앱이 고정(날짜 선택기 없음): 일 = 오늘 포함 7일, 주 = 이번 주 포함 8주(월요일 시작), 월 = 이번 달 포함 6개월. 모두 +09:00 날짜.
  • 기록이 없는 구간(sampleCount: 0)은 막대 없이 빈칸이고, 누르면 "기록 없음". 모든 구간이 비면 "이 기간에는 기록이 없어요."
  • 월 탭은 "기록은 90일만 보관돼 오래된 달은 비어 있을 수 있어요" 안내.
  • 고른 탭은 화면 회전 뒤에도 유지된다.

2흐름 그림 — 탭에서 막대까지

3코드 해설

① 주는 월요일부터

LocalDate monday = today.with(TemporalAdjusters.previousOrSame(DayOfWeek.MONDAY));
return new PeriodRange(monday.minusWeeks(7), today);
왜 서버는 주를 월요일 시작으로 자른다. 시작일을 아무 요일로 주면 첫 막대가 며칠짜리 반쪽 주가 된다. 이번 주 월요일에서 7주를 빼면 8개 막대가 모두 온전한 주(이번 주만 오늘까지)가 된다. 2026-11-24(화) 기준 시작은 10-05(월)이다. 변경 목록에 적었던 10-06은 화요일이라 고쳤다.

② "오늘"은 서버 기준 날짜

private static final ZoneOffset SERVER_OFFSET = ZoneOffset.ofHours(9);
public static LocalDate today() { return LocalDate.now(SERVER_OFFSET); }
왜 집계 날짜는 +09:00이다. 휴대폰 시간대가 다르면(해외 여행 등) 자정 근처에 "오늘"이 하루 어긋나 마지막 막대가 빠질 수 있다.

③ 0과 "기록 없음"은 다르다

boolean hasData = bucket.sampleCount > 0;
bars.add(new Bar(label, detail, hasData ? bucket.energyUsedMwh : 0L, hasData));
왜 기기가 켜져 있지만 전기를 안 썼으면 0 mWh, 기기가 꺼져 있거나 기록 보관 기간(90일) 밖이면 기록 자체가 없다. 둘 다 막대 높이는 0이지만 눌렀을 때 글자로 구분한다.

4용어 풀이

  • 집계 모드: 서버가 기록을 하루·주·달 단위로 합쳐 구간마다 사용량 하나를 주는 방식. 앱이 차이를 계산할 필요가 없다.
  • MaterialButtonToggleGroup: 버튼 여럿 중 하나만 눌린 상태로 두는 묶음. selectionRequired로 아무것도 안 고른 상태를 막는다.
  • onSaveInstanceState: 화면이 다시 만들어질 때 되살릴 작은 값(여기서는 고른 탭)을 담는 곳.
