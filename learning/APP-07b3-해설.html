APP-07b-3 해설 — 켜는 중·실패·빈 화면을 분명하게

ui-1 브랜치 · UI 1차 07b · UI-01·UI-02·UI-10, 사용자 결정(UNKNOWN 새로고침) · 2026-11-24

1한눈에 보기

  • 켜는 동안: 스위치를 누르면 응답이 올 때까지 누른 위치 그대로 잠그고 칩에 "켜는 중…/끄는 중…"을 보인다. 예전에는 LOADING이 되며 스위치가 원래 위치로 튀었다(UI-10).
  • 실패: 제어 실패는 토스트 대신 Snackbar로, "‘거실 전등’을 켜지 못했어요. (이유)" + 다시 시도(UI-01). 통신 실패의 영어 예외 문구 대신 "서버에 연결할 수 없어요."
  • 알 수 없음: UNKNOWN 타일에는 새로고침 버튼(48dp)이 생기고, 누르면 E5를 기기에 직접 묻는다(isManualRefresh=true).
  • 빈 화면: 기기가 0개면 안내 + "기기 추가" 버튼(UI-02). 아직 목록을 못 받았을 때(null)는 빈 화면을 보이지 않는다.
  • 깜빡임 줄이기: 홈이 들어올 때마다 부르는 전력 조회(E6)는 더 이상 타일을 LOADING("확인 중…")으로 바꾸지 않는다. 값만 조용히 바꾼다.

2흐름 그림 — 스위치 한 번

3코드 해설

① 보낸 명령을 기억해 두기

// DeviceViewModel.controlDevice
updateDevice(targetId, device -> device.setPendingCommand(command));
beginLoading(targetId);
…응답(성공·실패 모두)
updateDevice(targetId, device -> device.setPendingCommand(null));

// HomeTile
if (pending != null) {
    chipText = "ON".equals(pending) ? "켜는 중…" : "끄는 중…";
    switchChecked = "ON".equals(pending);
    switchEnabled = false;
}
왜 state가 아니라 따로 state는 LOADING이 되는 순간 "무엇을 요청했는지"를 잃는다. LOADING은 상태 조회·삭제에도 쓰여서 "켜는 중"인지 알 수 없다. 그래서 명령만 따로 transient 필드에 둔다.
빼면 켜기를 누르자마자 스위치가 꺼짐으로 돌아갔다가 성공하면 다시 켜진다. 사용자는 "안 눌렸나?" 하고 또 누른다.

② 실패를 "이벤트"로 보내고 화면이 고르기

private void reportControlFailure(String deviceId, String command, String reason) {
    controlFailure.setValue(new OneTimeEvent<>(
            new ControlFailure(deviceId, currentName(deviceId), command, reason)));
}
// MainActivity
Snackbar.make(container, failure.message, Snackbar.LENGTH_LONG)
        .setAnchorView(bottomNav)
        .setAction("다시 시도", v -> viewModel.controlDevice(failure.deviceId, failure.command))
        .show();
왜 토스트는 문구만 보낼 수 있다. "다시 시도"를 하려면 어느 기기에 어떤 명령이었는지가 함께 있어야 한다. OneTimeEvent로 감싸 화면 회전·탭 이동 때 다시 뜨지 않게 한다(APP-05와 같은 방법).
조사 "‘전등’을 / ‘플러그’를"처럼 마지막 글자 받침으로 을·를을 고른다. 한글 음절은 (글자 − 0xAC00) % 28 == 0이면 받침이 없다.

③ 조용한 전력 조회

BEFORE
beginLoading(deviceId);   // "확인 중…"
… finishLoading(deviceId, body.state);
AFTER
pendingStates.remember(deviceId, state);
if (state != null && !pendingStates.isPending(deviceId))
    device.setState(state);
왜 홈에 올 때마다 Matter 타일이 모두 "확인 중…"으로 바뀌었다 돌아오면 정신없다(목업: 로딩 대신 이전 값 유지). 다만 제어가 진행 중이면 그 결과가 우선이므로 isPending일 때는 상태를 건드리지 않는다.

4용어 풀이

  • Snackbar: 화면 아래에 잠깐 뜨는 알림 막대. 토스트와 달리 버튼(동작)을 하나 넣을 수 있다.
  • anchorView: Snackbar를 어느 뷰 위에 띄울지. 하단 탭을 가리지 않게 탭 위로 올린다.
  • 빈 상태(empty state): 보여 줄 것이 없을 때의 화면. 다음에 할 일(기기 추가)을 바로 누를 수 있게 한다.

5이해도 질문

  1. 켜기를 누르고 202(지연 수락)를 받으면 스위치는 어디에 있을까?
  2. 목록이 아직 안 왔을 때 빈 화면을 보이면 어떤 문제가 있을까?
  3. Snackbar의 "다시 시도"를 눌렀는데 기기가 그사이 오프라인이 됐다면?
정답 보기
  1. 202의 state는 바뀌기 전 상태라 꺼짐 위치로 돌아가고, "약 N초 뒤 켜집니다" 안내와 예약된 E5가 결과를 알려 준다(06b 그대로).
  2. 기기가 있는데도 잠깐 "등록된 기기가 없어요"가 보였다 사라져 사용자를 놀라게 한다. 그래서 null은 빈 화면이 아니다.
  3. 다시 E2를 보내고, 502면 OFFLINE + 새 Snackbar가 뜬다. 스위치는 오프라인이라 잠긴다.
