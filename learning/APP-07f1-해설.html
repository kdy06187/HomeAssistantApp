APP-07f-1 해설 — 연결 상태 한 곳에서 관리

ui-1 브랜치 · UI 1차 07f · F-01 · 2026-11-24

1한눈에 보기

  • 연결 상태 하나: 정상 / 서버에 닿지 않음 / 토큰 오류. 모든 요청의 결과(HTTP 코드 또는 통신 실패)가 바깥 인터셉터 ConnectionStateInterceptor를 거쳐 ConnectionState로 모인다.
  • F-01의 뿌리: 예전 401 처리는 "안내했음" 표시(UnauthorizedNotice)만 있어서, 첫 안내 뒤에는 틀린 토큰인 동안 아무것도 보이지 않았다. 이제 토큰 오류가 상태라서 고칠 때까지 계속 남고, 배너(07f-2)가 그 상태를 그린다.
  • 설정 화면의 토큰 칸 오류(07e-1)도 같은 상태(isTokenRejected)를 본다. 저장하면 onSettingsSaved가 상태를 처음으로 돌린다. 설정 탭 자동 이동은 토큰 오류로 바뀌는 순간 1번.

3코드 해설

if (httpCode == 401) next = Kind.TOKEN_ERROR;
else if (httpCode >= 200 && httpCode < 300) next = Kind.OK;
else next = kind == Kind.UNREACHABLE ? Kind.OK : kind;
왜 404·500은 토큰 오류를 안 푸나 틀린 토큰이면 서버는 모든 요청에 401을 준다. 2xx가 와야 토큰이 맞다고 확신할 수 있다. 반면 "닿지 않음"은 어떤 응답이든 오면 풀린다(서버가 살아 있으니까).
mainHandler.post(() -> connectionState.setValue(connection.get()));
왜 값 대신 "그때의 최신 값" OkHttp 스레드에서 postValue(TOKEN_ERROR)를 해 두면, 그 사이 사용자가 설정을 저장해 OK로 바꿔도 늦게 도착한 옛 값이 덮어쓸 수 있다. 메인 스레드에서 읽는 순간의 값을 내보내면 늘 최신이다.

4용어 풀이

  • 상태 기계: 정해진 상태와 "무슨 일이 생기면 어디로 가나" 규칙만으로 움직이는 구조.
  • synchronized: 여러 스레드가 동시에 바꿔도 한 번에 하나씩만 들어오게 하는 잠금.
