3코드 해설

① 인터페이스를 통째로 흉내 내기

(ImageProxy) Proxy.newProxyInstance(loader, new Class<?>[]{ImageProxy.class},
    (p, method, args) -> {
        switch (method.getName()) {
            case "getPlanes": return new PlaneProxy[]{plane};
            case "close": closed++; return null;
            default: throw new UnsupportedOperationException(method.getName());
        }
    });
무엇을 메서드가 많은 ImageProxy를 클래스로 다 구현하지 않고, 불리는 메서드 이름만 골라 답한다.
왜 CameraX 버전이 올라 메서드가 늘어도 시험 코드가 깨지지 않는다. 예상 못 한 메서드를 부르면 예외로 바로 드러난다.
빼면 실제 카메라가 필요해 Studio·실기기에서만 확인할 수 있었다(close를 빼먹으면 카메라가 프레임을 더 안 준다 — 화면이 멈춘 듯 보인다).

② 동시성 시험

CountDownLatch go = new CountDownLatch(1);
// 두 스레드가 go.await() 뒤 동시에 401·통신 실패를 200번씩
assertEquals(1, entered.get());
왜 07h-2에서 상태 변경과 "진입" 판단을 한 잠금 안에 넣었다. 잠금이 없으면 두 스레드가 모두 "내가 처음"이라고 판단해 안내가 두 번 나갈 수 있다. 50번 반복해 우연히 통과하는 일을 줄였다.

③ 바이트 경계

repeat("가", 10)  // 30바이트 → 통과
repeat("가", 11)  // 33바이트 → SSID 최대 32 넘음
repeat("😀", 16)  // 64바이트 → 비밀번호 최대 63 넘음
왜 Wi-Fi 규격은 글자 수가 아니라 UTF-8 바이트로 센다. 반대로 기기 이름은 서버가 글자(코드 포인트)로 세므로 이모지 하나가 한 글자다. 두 규칙이 다르다는 걸 시험이 지킨다.

4용어 풀이

  • 동적 프록시(Proxy): 실행 중에 인터페이스 구현 객체를 만들어, 모든 메서드 호출을 한 함수로 받는 Java 기능.
  • CountDownLatch: 여러 스레드를 같은 출발선에 세웠다가 한 번에 출발시키는 도구.
  • 경계값 시험: 허용 한계 바로 안쪽·바깥쪽 값을 넣어 보는 시험.
  • 코드 포인트: 사람이 보는 한 글자에 해당하는 유니코드 번호. 이모지는 UTF-16으로 2칸(서로게이트 쌍)이다.
