3코드 해설

조각 1 · 401이면 설정 화면으로 (#2) 인터셉터 + LiveData

// UnauthorizedInterceptor
Response response = chain.proceed(chain.request());
if (response.code() == 401) onUnauthorized.run();   // 응답은 손대지 않고 그대로 넘긴다
return response;

// RetrofitClient
if (unauthorizedPending.compareAndSet(false, true)) unauthorizedSignal.postValue(true);

// MainActivity
RetrofitClient.getUnauthorizedSignal().observe(this, s -> {
    if (!RetrofitClient.consumeUnauthorized()) return;  // 이미 처리한 401
    bottomNav.setSelectedItemId(R.id.nav_settings);
});
왜 인터셉터? · 401은 7개 API 어디서나 올 수 있다. 콜백마다 검사하면 하나를 빠뜨린다. 응답을 한 곳에서 보는 인터셉터라면 한 번만 짜면 된다.
왜 postValue? · 인터셉터는 OkHttp 백그라운드 스레드에서 돈다. setValue는 메인 스레드 전용이라 다른 스레드에서 부르면 앱이 죽는다.
왜 플래그를 따로? · LiveData는 새 관찰자에게 마지막 값을 다시 준다. 화면을 돌리면 MainActivity가 새로 생기면서 옛 401로 또 이동한다. "처리했다"는 표시를 AtomicBoolean으로 따로 둬서 한 번만 이동한다. 요청 다섯 개가 동시에 401을 받아도 토스트는 한 번이다.
빼면? · 토큰이 틀려도 "목록 로드 실패: 401" 토스트만 뜨고, 사용자는 무엇을 고쳐야 할지 모른다.

조각 4 · 제어 성공 판정과 400 처리 (#5, #6)

BEFORE

왜 OFFLINE이 아닌가? · 400은 "요청 모양이 틀렸다"는 뜻이지 기기가 꺼졌다는 뜻이 아니다. 새로 안 것이 없으니 원래 상태를 유지한다.

조각 7 · LOADING 되돌리기 (#11)

빼면? · 서버가 꺼진 상태에서 스위치를 누르면 그 기기는 앱을 다시 켤 때까지 계속 로딩 중으로 보인다.

4용어 풀이

인터셉터 사슬
OkHttp는 인터셉터를 추가한 순서대로 요청을 넘기고, 응답은 거꾸로 돌려준다. 그래서 응답을 살피는 인터셉터도 만들 수 있다.
setValue / postValue
LiveData에 값을 넣는 두 방법. setValue는 메인 스레드에서 바로 넣고, postValue는 어느 스레드에서든 메인 스레드로 넘겨서 넣는다.
AtomicBoolean.compareAndSet
"지금 값이 A면 B로 바꾸고 true"를 한 번에(쪼개지지 않게) 한다. 여러 스레드가 동시에 불러도 한 번만 성공한다.
UTC / 현지 시간
UTC는 기준 시각이고 한국은 UTC+9다. 시간대 정보가 없는 문자열은 어느 시간대인지 직접 알려 줘야 한다.
순수 자바 클래스
Android 화면이나 Context를 쓰지 않는 클래스. 폰 없이 PC에서 JUnit으로 바로 테스트할 수 있다.

5이해도 질문

  1. UnauthorizedInterceptor가 401 응답을 "삼키지" 않고 그대로 넘기는 이유는?
    정답 보기ViewModel의 콜백이 평소처럼 실패 갈래를 타야 LOADING이 풀린다(#11). 인터셉터는 "알리기"만 하고, 화면 정리는 각 콜백이 한다.
  2. 기기 등록 요청의 읽기 타임아웃은 몇 초인가? 목록 조회는?
    정답 보기경로로 정한다. /api/commission은 150초, /api/devices는 기본 60초.
  3. 서버가 E2에 {"status": null, "message": "명령 성공!"}을 주면 화면 상태는?
    정답 보기성공으로 판정하지만 stateOr(null, previous)로 요청 전 상태를 유지한다. null로 덮어쓰지 않는다.

실습 A · 오류 메시지를 message/error에서 읽기 (불일치 #13) 조각 4 응용

목표E2·E3·E4의 400 응답에서 서버 문구(예: "허용되지 않은 명령입니다.")를 토스트에 보여 준다. 지금은 "제어 실패: 400"처럼 코드만 나온다. 고칠 파일network/ErrorMessages.java(새로 만듦), viewmodel/DeviceViewModel.java, 테스트 network/ErrorMessagesTest.java 완료 기준① {"result":"error","message":"X"} → "X" ② {"error":"Y"} → "Y" ③ JSON이 아니면 null ④ 빌드와 기존 23개 테스트 통과
힌트
  • 판정은 문자열을 받는 순수 함수로 만든다: static String fromJson(String body). 조각 5·6과 같은 방식이라 테스트하기 쉽다.
  • JsonParser.parseString(body).getAsJsonObject()로 읽고, has("message")를 먼저, 없으면 has("error")를 본다.
  • ViewModel에서는 response.errorBody().string()을 넘긴다. string()은 한 번만 읽을 수 있다.
정답 보기 
public final class ErrorMessages {
    private ErrorMessages() {}
    /** 계약서 §4.3: message 또는 error 중 있는 키에서 읽는다. 없거나 JSON이 아니면 null. */
    public static String fromJson(String body) {
        if (body == null) return null;
        try {
            JsonObject o = JsonParser.parseString(body).getAsJsonObject();
            if (o.has("message")) return o.get("message").getAsString();
            if (o.has("error")) return o.get("error").getAsString();
        } catch (RuntimeException ignored) { }
        return null;
    }
}

// DeviceViewModel.controlDevice()의 else 갈래
String detail = null;
try { if (response.errorBody() != null) detail = ErrorMessages.fromJson(response.errorBody().string()); }
catch (IOException ignored) { }
toastMessage.setValue("제어 실패: " + (detail != null ? detail : String.valueOf(response.code())));

// 테스트
// message 키에서 읽는다
@Test
public void messageKey_isRead() {
    assertEquals("X", ErrorMessages.fromJson("{\"result\":\"error\",\"message\":\"X\"}"));
}

실습 B · 차트를 구간 사용량으로 (불일치 #14) 조각 6 응용

목표E7의 totalEnergy_mWh는 누적값이라 그래프가 계속 오르기만 한다. 이웃한 두 기록의 차이(구간 사용량)를 그린다. 고칠 파일view/EnergyLogTimeline.java에 intervalUsage() 추가, view/EnergyLineChartView.java, 테스트 완료 기준① 오래된 순 [100, 200, 350] → [100, 150] ② 기록이 1개 이하면 빈 목록 ③ 차이가 음수(계량기 초기화)면 0 ④ 테스트 통과
힌트
  • 반드시 oldestFirst()로 정렬한 뒤에 차이를 구한다. 순서가 거꾸로면 모두 음수가 된다.
  • 점 개수가 하나 줄어든다. X축 라벨은 구간이 끝난 시각(i번째 기록)을 쓴다.
정답 보기 
/** 오래된 순 로그에서 이웃한 두 값의 차이. 음수면 0(계량기 초기화 등). */
public static List<Long> intervalUsage(List<EnergyLog> oldestFirst) {
    List<Long> result = new ArrayList<>();
    for (int i = 1; i < oldestFirst.size(); i++) {
        long diff = oldestFirst.get(i).getTotalEnergy_mWh() - oldestFirst.get(i - 1).getTotalEnergy_mWh();
        result.add(Math.max(0, diff));
    }
    return result;
}
