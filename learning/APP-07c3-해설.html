APP-07c-3 해설 — 사용량 막대 차트

ui-1 브랜치 · UI 1차 07c · UI-14(차트 단위·제목·빈 상태) · 2026-11-24

1한눈에 보기

  • 전: 옛 상세는 선 차트였고 단위·제목이 없었다. 기록이 1개뿐이면 빈 차트에 영어 안내가 떴다.
  • 후: 상세에 막대 차트 카드. 제목 "구간별 사용량 (Wh)"처럼 단위가 붙고, 막대를 누르면 "09:22 · 0.5 Wh"가 위에 보인다.
  • 단위 자동: 가장 큰 막대가 1000 mWh를 넘으면 Wh, 1,000,000을 넘으면 kWh. 한 차트 안 막대는 모두 같은 단위.
  • 빈 상태: 기록 2개 미만이면 "기록이 쌓이는 중이에요". 실패하면 이유 + "다시 시도". 서버가 잘랐으면(truncated) "최근 50건만 보여요."
  • 상태가 "확인 중…"으로 바뀌지 않는다(옛 상세는 차트를 받는 동안 기기 상태를 LOADING으로 바꿨다).

2흐름 그림 — 기록에서 막대까지

3코드 해설

① 계산과 그리기를 나눈다

ChartBars bars = ChartBars.fromLogs(logs, truncated, TimeZone.getDefault());
chartCard.bind(bars, false);   // 카드는 글자만, 차트는 막대만
왜 MPAndroidChart는 Android 뷰라 단위 테스트에서 만들 수 없다. 막대 값·라벨·단위·빈 상태 문구를 순수 클래스 ChartBars로 만들어 두면 "누적값이 줄면 0" "기록 1개면 빈 상태" 같은 규칙을 테스트로 확인할 수 있다. 07c-4의 일/주/월도 같은 모양으로 바꿔 넣기만 하면 된다.

② 단위는 가장 큰 막대 기준

public static Unit unitFor(long maxMwh) {
    if (maxMwh >= 1_000_000) return Unit.KWH;
    if (maxMwh >= 1_000) return Unit.WH;
    return Unit.MWH;
}
왜 막대마다 단위가 다르면 높이를 비교할 수 없다. 가장 큰 값이 1~999 사이 숫자가 되는 단위를 하나 골라 모든 막대를 그 단위로 나눈다. 그래서 작은 막대는 "0.15 Wh"처럼 소수가 된다.

③ 늦게 온 응답은 버린다

if (!deviceId.equals(historyDeviceId)) return;
왜 A 기기 상세를 열었다가 바로 B로 가면 A의 응답이 B 화면에 그려질 수 있다. ViewModel이 마지막으로 요청한 기기만 기억해 다른 응답은 무시한다. 화면 회전 때는 받아 둔 결과를 다시 쓰고, 새로 열면 새로 묻는다.

4용어 풀이

  • 누적값과 구간 사용량: 기기는 "지금까지 쓴 양"을 준다. 막대는 이웃한 두 기록의 차이, 즉 그 사이에 쓴 양이다.
  • BarEntry: MPAndroidChart 막대 하나(x 위치, 높이).
  • contentDescription 요약: TalkBack은 막대를 하나씩 읽지 못하므로 "막대 N개, 가장 많은 구간 …"을 한 문장으로 준다.

5이해도 질문

  1. 기록이 50개면 막대는 몇 개일까?
  2. 막대 값이 150, 1500, 400 mWh면 제목과 첫 막대 글자는?
정답 보기
  1. 49개. 이웃 둘의 차이라서 하나 적다.
  2. "구간별 사용량 (Wh)", 첫 막대는 "0.15 Wh". 가장 큰 1500이 Wh 단위를 정한다.
