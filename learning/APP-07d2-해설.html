1한눈에 보기

  • QR 스캔 화면 QrScanFragment: CameraX로 미리보기를 띄우고, 프레임마다 ZXing으로 QR을 찾는다. MT:로 시작하는 Matter QR이면 입력 화면으로 돌아가 바로 등록을 시도한다.
  • 권한 4단계: 처음엔 설명 → 시스템 창, 한 번 거부하면 "다시 요청", 다시 묻지 않음이면 "설정에서 허용"(앱 설정 화면). 판단은 순수 함수 CameraPermissionStep.
  • QR 내용은 남기지 않는다: 로그 없음, prefs·Bundle 저장 없음, 화면에는 앞 6자만("MT:Y3.…"). 넘길 때도 메모리에만 있는 ViewModel을 쓴다.
  • 버전: CameraX 1.6.2(1.7.0은 11-18에 나와 아직 2주가 안 됨), ZXing core 3.5.4(변경 목록의 1.4.2·3.5.3보다 새 안정판).

2흐름 그림 — QR 한 장이 입력 화면까지

3코드 해설

① 밝기 값만으로 QR 읽기

PlanarYUVLuminanceSource source = new PlanarYUVLuminanceSource(
        luminance, rowStride, height, 0, 0, width, height, false);
Result result = reader.decode(new BinaryBitmap(new HybridBinarizer(source)), hints);
무엇을 카메라 YUV 이미지의 첫 면(Y)은 픽셀마다 밝기 1바이트다. QR은 흑백이라 이것만 있으면 된다.
왜 rowStride 카메라는 메모리 정렬 때문에 한 줄 끝에 빈 바이트를 붙이기도 한다. 줄 길이를 width로 착각하면 그림이 비스듬히 밀려 못 읽는다. 테스트 decodesWithRowPadding이 이 경우를 본다.
빼면(reset) reader.reset()을 안 하면 앞 프레임 상태가 남아 다음 해석에 영향을 줄 수 있다.

② 영구 거부를 알아내는 방법

if (granted) return START_CAMERA;
if (!askedBefore) return EXPLAIN_FIRST;
return showRationale ? ASK_AGAIN : OPEN_SETTINGS;
무엇을 Android는 "다시 묻지 않음"을 직접 알려 주지 않는다. 대신 shouldShowRequestPermissionRationale가 "처음"과 "영구 거부" 둘 다에서 false다.
왜 askedBefore 그래서 한 번이라도 물어봤는지를 prefs에 따로 적는다(QR 내용이 아니라 true/false 하나). 물어본 적이 있는데 false면 영구 거부로 본다.

③ 저장하지 않고 넘기기

흔한 방법(안 씀)
getParentFragmentManager()
    .setFragmentResult("qr", bundle);
이번 방법
new ViewModelProvider(requireActivity())
    .get(QrScanResult.class).deliver(payload);
왜 Fragment 결과 Bundle은 아직 안 꺼낸 채 앱이 백그라운드로 가면 저장 상태에 함께 들어가 디스크에 쓰일 수 있다. ViewModel은 메모리에만 있다. 입력 화면도 같은 이유로 스캔 값을 Draft ViewModel에 둔다(onSaveInstanceState에 안 넣음).

4용어 풀이

  • CameraX: 카메라를 화면 수명 주기에 묶어 켜고 끄는 Jetpack 라이브러리. bindToLifecycle로 묶으면 화면이 사라질 때 알아서 풀린다.
  • ImageAnalysis: 프레임을 받아 직접 계산하는 CameraX 기능. KEEP_ONLY_LATEST는 계산이 밀리면 오래된 프레임을 버린다.
  • ZXing: 바코드·QR을 만들고 읽는 Java 라이브러리(Apache 2.0). 순수 Java라 단위 테스트에서 QR을 그려 다시 읽어 볼 수 있다.
  • rationale: "왜 이 권한이 필요한지" 설명을 보여 줄 때인지 시스템이 알려 주는 값.
  • uses-feature required=false: 카메라 없는 기기도 설치는 되게 한다. 그런 기기에서는 스캔 버튼을 숨긴다.

정답 보기
  1. volatile boolean done. 읽자마자 true로 바꾸고, 다음 프레임부터는 바로 닫는다.
  2. ASK_AGAIN(물어봤음 + rationale true). 두 번째 거부 뒤에는 보통 rationale이 false가 되어 OPEN_SETTINGS.
  3. 닫지 않으면 CameraX가 다음 프레임을 보내지 않아 분석이 멈춘다. 해석 실패·예외에도 꼭 닫아야 한다.

6응용 실습

새 브랜치나 learning/exercise-qr/ 사본에서 해 보세요.

실습 1 — 반전 QR 테스트

목표: 흰 바탕 검은 QR 대신 검은 바탕 흰 QR(색 반전)도 읽히는지 시험한다. 고칠 파일: QrDecoderTest. 완료 기준: 테스트가 실패하면 왜 실패하는지 설명할 수 있다.

힌트luminance()에서 0과 255를 바꾼다. ZXing QRCodeReader는 기본으로 반전을 시도하지 않는다.
정답실패한다(null). 읽게 하려면 실패했을 때 source.invert()로 만든 반전 이미지로 한 번 더 decode한다. Matter QR은 보통 반전되지 않아 이번엔 넣지 않았다.

실습 2 — 표시 글자 수 바꾸기

목표: 앞 6자 대신 4자("MT:Y…")만 보이게 한다. 고칠 파일: QrPayload.java, QrPayloadTest. 완료 기준: 테스트를 함께 고쳐 통과.

정답SHOWN_CHARS = 4, 테스트 기대값 "MT:Y…".
