ui-1 브랜치 · UI 1차 07a · 2026-11-24 · 사용자 결정: UNKNOWN은 바로 "알 수 없음"(주황)

1한눈에 보기

  • 전: DeviceStateLabel은 문구만 알았다(ON·OFF 둘 다 "연결됨"). 색은 DashboardAdapter의 switch에, LOADING은 어댑터의 별도 if에 흩어져 있었다.
  • 후: 상태 하나 → 문구 + 칩 색쌍(Tone) + 스위치 가능 여부를 Kind 열거형 한 줄에 묶었다. 화면은 kindOf(state)만 부르고 그 값을 그대로 쓴다.
  • 화면 변화: 대시보드 섹션의 상태 글자가 색 바탕 칩이 되고, "연결됨" 대신 켜짐 / 꺼짐, 요청 중에는 확인 중…이 보인다.

OFF꺼짐회색(OFF)가능

2흐름 그림

3코드 해설

① 열거형 한 줄에 규칙 하나

public enum Kind {
    ON("켜짐", Tone.ON, true),
    OFF("꺼짐", Tone.OFF, true),
    OFFLINE("오프라인", Tone.OFFLINE, false),
    UNKNOWN("알 수 없음", Tone.WARNING, false),
    LOADING("확인 중…", Tone.WARNING, false);
    …
}
무엇을 상태마다 "무엇이라 쓰고, 무슨 색이고, 눌러도 되는지"를 한 줄에 적는다. 새 상태가 생기면 이 줄 하나만 더하면 된다.
왜 문구·색·잠금이 여러 파일에 흩어지면 홈 타일(07b)·기기 탭·상세(07c)가 서로 다르게 보이기 쉽다. 세 화면 모두 이 열거형을 읽게 한다.
빼면(어댑터마다 switch) 예를 들어 상세는 UNKNOWN을 "확인 중", 홈은 "알 수 없음"으로 쓰는 식의 엇갈림이 생긴다.

② 색쌍은 리소스 ID로

public enum Tone {
    ON(R.color.state_on_bg, R.color.state_on_fg), …
    @ColorRes public final int background;
    @ColorRes public final int foreground;
}

private static void applyTone(TextView chip, DeviceStateLabel.Tone tone) {
    chip.setTextColor(ContextCompat.getColor(chip.getContext(), tone.foreground));
    ViewCompat.setBackgroundTintList(chip,
            ColorStateList.valueOf(ContextCompat.getColor(chip.getContext(), tone.background)));
}
왜 ID인가 실제 색 값은 라이트·다크마다 다르다. 열거형은 "어느 토큰"만 들고, 값은 화면에 그릴 때 Context가 고른다. 그래서 단위 테스트(Android 없이)에서도 Tone.ON.foreground == R.color.state_on_fg를 확인할 수 있다.
칩 모양 bg_state_chip.xml은 흰 둥근 사각형이고, backgroundTint로 상태 색을 칠한다. 모양 하나로 네 가지 색을 낸다.

③ 모르는 값은 안전한 쪽으로

public static Kind kindOf(String state) {
    if (state == null) return Kind.UNKNOWN;
    switch (state) {
        case "ON": return Kind.ON;
        …
        default: return Kind.UNKNOWN;   // 스위치 잠금
    }
}
왜 서버가 새 상태(예: STANDBY)를 보내도 앱이 죽지 않고, 확인되지 않은 기기를 실수로 켜지 않도록 스위치를 잠근다. 사용자 결정대로 "확인 중"으로 기다리지 않고 바로 "알 수 없음"을 보이고, 새로고침은 07b에서 버튼으로 붙인다.

4용어 풀이

  • 열거형(enum)에 필드 달기: 각 상수가 생성자 인자로 값(문구·색·플래그)을 갖게 하는 Java 문법. 표를 코드로 옮긴 것과 같다.
  • @ColorRes: "이 int는 색 리소스 ID"라는 표시. 실수로 색 값(0xFF…)을 넣으면 lint가 경고한다.
  • backgroundTint: 배경 모양은 그대로 두고 색만 덧칠하는 속성.

5이해도 질문

  1. 서버가 "on"(소문자)을 보내면 무엇이 보일까? 왜 그렇게 두었을까?
  2. LOADING과 UNKNOWN은 같은 주황색이다. 사용자는 둘을 어떻게 구분할까?
  3. canToggle은 지금 어디서 쓰일까?
정답 보기
  1. "알 수 없음"(주황, 잠금). 계약서의 값은 대문자라 약속 밖의 값은 모두 같은 안전한 처리로 둔다.
  2. 문구("확인 중…" / "알 수 없음")와 LOADING일 때 도는 진행 표시로 구분한다. 색만으로 뜻을 전하지 않는 것이 접근성 원칙이다.
  3. 아직 화면에서는 쓰지 않는다. 07b-2·07b-3의 홈 타일 스위치가 이 값으로 잠긴다(지금의 위젯 스위치는 07b에서 없어진다).
