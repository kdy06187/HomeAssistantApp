ui-1 브랜치 · UI 1차 07a · 2026-11-24 · 07a-1의 토큰을 실제 화면에 연결

1한눈에 보기

  • 전: 레이아웃 11개 파일과 Java 2개 파일에 #333333, Color.parseColor("#4CAF50") 같은 값이 있었다. 다크 모드에서 흰 카드·검은 아이콘이 그대로 남는다. 12·13sp 글자도 있었다.
  • 후: 레이아웃은 ?attr/colorOnSurface 같은 테마 속성, 상태 색은 @color/state_*_fg 토큰을 쓴다. Java는 MaterialColors.getColor(view, attr)·ContextCompat.getColor(ctx, R.color.…)로 읽는다. 글자는 모두 14sp 이상.
  • 지킴이 테스트: HardcodedStyleTest가 레이아웃·아이콘·Java를 읽어 색 값이나 14sp 미만 글자가 다시 들어오면 실패한다.

2흐름 그림 — 어디서 색을 읽나

3코드 해설

① 레이아웃: 값 → 역할

BEFORE
android:textSize="12sp"
android:textColor="#888888"
AFTER
android:textSize="14sp"
android:textColor="?attr/colorOnSurfaceVariant"
왜 #888888은 흰 배경에서 대비가 약 3.5:1이라 기준(4.5:1)에 못 미친다. colorOnSurfaceVariant는 라이트 #49454F, 다크 #CAC4D0이라 두 테마 모두 기준을 넘는다(07a-1 테스트).

② Java: 뷰가 속한 테마에서 읽기

BEFORE
holder.tvDeviceStatus.setTextColor(
    Color.parseColor("#4CAF50"));
AFTER
holder.tvDeviceStatus.setTextColor(
    ContextCompat.getColor(holder.itemView.getContext(),
        R.color.state_on_fg));
무엇을 ContextCompat.getColor는 지금 설정(다크 여부)에 맞는 colors.xml 값을 준다. 테마 속성은 MaterialColors.getColor(view, R.attr.colorOnSurfaceVariant)로 읽는다.
주의 colorPrimary는 AppCompat이 정의한 속성이라 androidx.appcompat.R.attr.colorPrimary, colorOnSurfaceVariant는 Material이 정의해서 com.google.android.material.R.attr…이다. 라이브러리마다 자기 R이 따로 있다.

③ 차트는 테마를 모른다

int labelColor = MaterialColors.getColor(this, com.google.android.material.R.attr.colorOnSurfaceVariant);
getXAxis().setTextColor(labelColor);
getAxisLeft().setTextColor(labelColor);
setNoDataTextColor(labelColor);
왜 MPAndroidChart는 Android 테마를 읽지 않고 축 글자를 검정으로 그린다. 다크 배경에서 축이 사라지므로 직접 넣는다.
빼면 다크 모드에서 차트 축 시간·숫자가 보이지 않는다.

④ 지킴이 테스트

Pattern XML_COLOR = Pattern.compile("=\"#[0-9A-Fa-f]{3,8}\"");
Pattern JAVA_COLOR = Pattern.compile("Color\\.(parseColor|rgb|argb|[A-Z]+\\b)");
왜 색 값 하나는 리뷰에서 놓치기 쉽다. 파일을 읽는 단위 테스트가 있으면 새 화면(07b~07f)에서 실수해도 바로 빨간불이 켜진다. 런처 아이콘은 브랜드 색이라 뺐다.

4용어 풀이

  • ?attr/…: "지금 테마가 정한 값"을 가리키는 참조. @color/…는 색 리소스를 바로 가리킨다.
  • cardBackgroundColor: androidx CardView의 바탕색. 안쪽 레이아웃 바탕만 바꾸면 모서리에 CardView 기본색이 보일 수 있어 함께 정했다.
  • sp: 사용자 글꼴 크기 설정을 따르는 글자 단위. 14sp는 본문 최소 크기로 잡았다.

5이해도 질문

  1. 상태 글자색은 왜 테마 속성이 아니라 @color/state_on_fg 토큰을 직접 쓸까?
  2. 벡터 아이콘의 android:tint="?attr/colorOnSurface"는 왜 minSdk 26에서 문제없이 동작할까?
  3. HardcodedStyleTest가 있는데도 Studio 화면 확인이 필요한 이유는?
정답 보기
  1. Material 3에는 "켜짐 초록" 같은 역할이 없다. 앱만의 역할이라 토큰으로 둔다(라이트·다크 값은 토큰 파일이 고른다).
  2. 벡터 드로어블의 테마 속성 tint는 Android 7.0(API 24)부터 지원된다. 최소 버전이 8.0이라 안전하다.
  3. 테스트는 "직접 쓴 값이 없다"만 안다. 실제 겹침·그림자·라이브러리 기본색(예: 대화상자, 스피너)은 화면에서 봐야 한다.
