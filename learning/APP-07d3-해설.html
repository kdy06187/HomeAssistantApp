1한눈에 보기

  • 토스트 → 진행 화면: 등록 안내 토스트 5종을 없애고 CommissionProgressFragment 한 화면으로 모았다. 보이는 것은 서버가 알려 준 상태(대기 중 → 등록 중)와 경과 시간(mm:ss)뿐이다. "기기 찾는 중" 같은 세부 단계는 서버가 주지 않으므로 지어내지 않는다.
  • 결과는 사라지지 않는다: 성공·실패·확인 불가를 "확인"을 누를 때까지 남긴다. 실패는 "무슨 일 + 어떻게 하면 되는지" 두 문장.
  • 화면을 떠나도 계속: 등록은 액티비티 범위 ViewModel이 하므로 탭을 옮겨도 계속된다. 추가 버튼이 "등록 진행 보기"로 바뀌어 다시 들어올 수 있고, 다른 화면에서 결과가 나오면 Snackbar "보기"가 뜬다.
  • 서버 새 오류: 등록 요청(E3)이 502 DEVICE_UNREACHABLE이면 "서버가 종료되거나 다시 시작하는 중"으로 안내한다.

2흐름 그림 — 상태가 바뀌는 길

3코드 해설

① 토스트 대신 상태를 내보낸다

전
case SUCCEEDED:
    endCommission();
    showToast(CommissionPoller.successMessage(restored));
    fetchDevices();
후
case SUCCEEDED:
    endCommission();
    finishCommission(current.succeeded(restored));
    fetchDevices();
무엇을 finishCommission은 결과 상태를 LiveData에 두고(화면이 계속 봄), "방금 끝남" 이벤트도 1번 보낸다(다른 화면이면 Snackbar).
왜 토스트는 2초 뒤 사라져 놓치기 쉽다. 결과는 사용자가 확인할 때까지 남아야 한다.
빼면(이벤트) 홈에 있는 사람은 결과가 나왔는지 모르고 지나간다.

② 경과 시간은 서버 시각이 아니라 폰 시계로

String elapsed = status.startedAtMs > 0 ? mmss(nowMs - status.startedAtMs) : null;
...
ticker.postDelayed(this, TICK_MS);   // onStart~onStop 동안만 1초마다 render()
무엇을 202를 받은 순간의 SystemClock.elapsedRealtime()을 기억하고, 화면이 보일 때만 1초마다 다시 계산한다.
왜 elapsedRealtime 사용자가 폰 시간을 바꿔도 거꾸로 가지 않는 시계라서. 서버 폴링 간격(2초)과 따로 움직이므로 숫자가 부드럽게 오른다.

③ 화면 문구를 순수 함수로

CommissionScreen screen = CommissionScreen.of(status, SystemClock.elapsedRealtime());
textTitle.setText(screen.title);
bindButton(btnPrimary, screen.primary, screen.primaryLabel);
왜 어떤 오류에 어떤 제목·버튼을 보일지(14가지 정도)를 Android 없이 단위 테스트로 확인할 수 있다. Fragment는 받아서 그리기만 한다.

4용어 풀이

  • 값 객체(immutable): 만든 뒤 바뀌지 않는 객체. 상태가 바뀌면 새 객체를 만들어 LiveData에 넣는다.
  • acknowledge: "결과를 봤다"는 표시. 이때 상태를 비워 다음 추가 버튼이 입력 화면을 연다.
  • OnBackPressedCallback: 시스템 뒤로 가기를 화면이 가로채 직접 처리하는 장치.
  • accessibilityLiveRegion: 글자가 바뀌면 TalkBack이 알아서 읽게 하는 속성. 상태 제목에 걸었다.

5이해도 질문

  1. REJECTED일 때 뒤로 가기를 누르면 어디로 가나? RUNNING일 때는?
  2. 진행 화면이 안 보일 때 1초 타이머가 돌지 않는데도, 다시 열면 경과 시간이 맞는 이유는?
  3. "확인 불가(UNCONFIRMED)" 화면이 "다시 시도" 대신 "기기 목록 보기"를 주 버튼으로 둔 이유는?
정답 보기
  1. REJECTED는 입력 화면(값이 남아 있음)으로, RUNNING은 등록을 그대로 두고 탭으로 돌아간다.
  2. 시작 시각만 저장하고 매번 "지금 − 시작"을 계산하기 때문. 숫자를 하나씩 더하는 방식이 아니다.
  3. 실제로는 등록이 됐을 수 있다. 바로 다시 보내면 "이미 등록됨"이 되거나 기기를 헷갈리게 하므로 목록을 먼저 보게 한다.

실습 1 — 오래 걸릴 때 한 줄 더

목표: RUNNING이 2분을 넘으면 본문 끝에 "Matter 기기는 3분 넘게 걸릴 수 있어요."를 붙인다. 고칠 파일: CommissionScreen.java, CommissionScreenTest. 완료 기준: 1:59에는 없고 2:00부터 보이는 테스트 통과.

힌트nowMs - status.startedAtMs >= 120_000을 RUNNING 분기에서 본다. 세부 단계를 지어내는 것이 아니라 시간만 보고 하는 안내라 결정과 어긋나지 않는다.
정답
case RUNNING:
    String body = "서버가 기기를 등록하고 있어요. " + KEEPS_GOING;
    if (nowMs - status.startedAtMs >= 120_000) body += " Matter 기기는 3분 넘게 걸릴 수 있어요.";
    return progress("등록 중", body, ...);

실습 2 — 409 문구 시험 하나 더

목표: HTTP 코드 없이 errorCode만 COMMISSION_BUSY인 경우도 같은 제목인지 테스트한다. 완료 기준: 테스트 통과.

정답CommissionStatus.rejected("a", 422, "COMMISSION_BUSY", null) → 제목 "다른 기기를 등록하고 있어요".
