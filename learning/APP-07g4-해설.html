APP-07g-4 해설 — 타일 꾸미기 시트

ui-1 브랜치 · UI 1차 07g · D13(하단 시트)·D15(바로 저장 + 기본값) · 2026-11-24

1한눈에 보기

  • 여는 곳 두 군데: 상세 앱바 메뉴 "타일 꾸미기"(07c에서 자리만 있던 것), 기기 탭 줄의 꾸미기 버튼(조절 아이콘, 48dp, "○○ 타일 꾸미기"). 홈 타일 길게 누르기는 쓰지 않는다.
  • 시트 내용: 미리보기 타일 → 스위치 3개(현재 전력, 누적 사용량, 추이선) → 크기 1칸/2칸 → "기본값으로".
  • 바로 저장: 스위치를 바꾸는 순간 TilePrefs에 저장하고 미리보기를 다시 그린다. "저장" 버튼이 없다.
  • TCP_DIY는 스위치 3개를 숨기고 "크기만 바꿀 수 있어요" 안내를 보인다.
  • 미리보기는 홈 타일과 같은 그리기 코드를 쓰고, 누를 수 없다.

2흐름 그림 — 스위치 한 번

3코드 해설

① 화면을 맞출 때는 저장하지 않는다

binding = true;
power.setChecked(config.power);   // 리스너가 불려도
binding = false;
...
if (!binding) save(next);          // 여기서 걸러진다
왜 setChecked도 체크 리스너를 부른다. 막지 않으면 "기본값으로"를 누를 때 스위치를 하나씩 맞추는 동안 중간 상태가 저장되거나, 저장 → 다시 그림 → 저장이 되풀이된다.

② 미리보기는 홈 그리기 코드를 다시 쓴다

HomeTileAdapter.bindPreview(previewTile, HomeTile.of(device, config), trend);
왜 홈 어댑터의 그리기를 "보이는 부분(bindLook)"과 "누르면 하는 일"로 나눴다. 미리보기는 보이는 부분만 쓰고 스위치를 잠근다. 그래서 미리보기와 실제 홈 타일이 다를 수 없다. TalkBack은 미리보기를 한 문장("미리보기: 거실 플러그, 켜짐, 12.4 W, … 1칸")으로 읽는다.

③ 1칸/2칸 미리보기는 빈칸 무게로

spacer.weight = tile.span == 2 ? 0f : 1f;
왜 미리보기 타일과 빈 View가 가로로 무게 1:1이면 홈의 1칸과 같은 폭(반)이 된다. 빈칸 무게를 0으로 하면 타일이 한 줄을 다 쓴다.

4용어 풀이

  • BottomSheetDialogFragment: 아래에서 올라오는 시트. 회전해도 FragmentManager가 다시 띄운다(AlertDialog와 다름).
  • getChildFragmentManager: Fragment 안에 띄우는 Fragment(시트)를 관리. 부모 화면이 닫히면 같이 닫힌다.

5이해도 질문

  1. 기기 탭에서 시트를 열고 추이선을 켠 뒤 홈 탭으로 가면 추이선이 보일까?
  2. 시트를 열어 둔 사이 다른 폰에서 그 기기를 삭제했고, 목록이 새로 오면?
정답 보기
  1. 보인다. 저장은 이미 됐고, 홈은 새로 만들어질 때 TilePrefs를 읽는다. 선 값은 미리보기 때 받아 둔 캐시를 쓰거나 새로 묻는다.
  2. 시트가 스스로 닫힌다(목록에서 기기를 못 찾으면 dismiss).
