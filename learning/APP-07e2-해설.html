1한눈에 보기

  • 연결 테스트: 설정을 저장하지 않고, 지금 입력한 IP·포트·토큰으로 임시 클라이언트를 만들어 기기 목록(E1)을 한 번 부른다. 결과는 성공 / 토큰 오류(401) / 연결 불가 / 서버 오류(그 밖의 HTTP) 네 가지로 버튼 아래에 보인다.
  • 첫 실행(D8): 토큰이 저장된 적 없으면 저장 버튼이 "저장하고 시작하기"가 되고, 지금 입력과 같은 값으로 테스트가 성공했을 때만 눌린다. 저장하면 홈 탭으로 간다. 다시 들어온 경우에는 테스트 없이 저장할 수 있다(서버가 꺼져 있어도 주소를 바꿀 수 있게).
  • 임시 클라이언트는 401이어도 전역 안내·설정 탭 이동을 하지 않는다. 토큰 칸이 비었으면 저장된 토큰으로 테스트한다.

2흐름 그림 — 첫 실행

3코드 해설

① 저장하지 않는 임시 클라이언트

new OkHttpClient.Builder()
        .connectTimeout(5, TimeUnit.SECONDS)
        .addInterceptor(new AuthInterceptor(() -> token))   // 401 감시 인터셉터는 넣지 않음
        .build();
왜 앱 전체가 쓰는 클라이언트를 바꾸면, 틀린 주소로 테스트만 해도 다른 탭의 요청이 모두 실패한다. 401 감시를 넣으면 테스트 한 번에 "토큰이 맞지 않습니다" 토스트와 탭 이동이 일어난다.

② "같은 입력으로 성공했나"만 본다

public static boolean canSave(boolean firstRun, String testedInputs, String currentInputs) {
    if (!firstRun) return true;
    return testedInputs != null && testedInputs.equals(currentInputs);
}
무엇을 성공한 순간의 "IP·포트·토큰" 묶음을 기억하고, 글자가 바뀔 때마다 지금 묶음과 비교한다.
빼면 테스트 성공 뒤 토큰을 한 글자 바꿔도 저장되어, 첫 실행부터 401을 만난다.

4용어 풀이

  • 임시 클라이언트: 한 번 쓰고 버리는 Retrofit/OkHttp 객체. 전역 설정을 건드리지 않는다.
  • Call.cancel(): 진행 중 요청을 끊는다. 화면이 사라질 때 불러 결과가 빈 화면에 그려지지 않게 한다.
  • IOException: 연결 거부·시간 초과처럼 서버에 닿지 못한 실패.

5이해도 질문

  1. 테스트가 404를 받았다. 성공인가, 무엇을 의심해야 하나?
  2. 두 번째 실행부터는 왜 테스트 없이 저장할 수 있게 했나?
정답 보기
  1. 실패(SERVER_ERROR). 서버에는 닿았지만 경로가 없으니 다른 프로그램의 주소·포트일 수 있다.
  2. 서버가 꺼져 있을 때도 주소를 고칠 수 있어야 하기 때문(D8 A).
