APP-07h-8 해설 — QR 네모를 빈 곳에 맞추기

ui-1 브랜치 · 에뮬레이터 확인 문제 E4 · 2026-11-28

1한눈에 보기

  • 가로 화면에서 240dp 고정 스캔 네모가 아래 안내 글자·"직접 입력" 버튼과 겹쳤다.
  • 이제 네모는 위 도구 막대와 아래 안내 사이의 빈 곳을 재서, 그 안에 들어가는 크기(최대 240dp)로 빈 곳 가운데에 놓인다.
  • layout-land(가로용 레이아웃 한 벌 더)는 고르지 않았다. 같은 화면을 두 군데서 고쳐야 하기 때문이다. 짧은 변 기준만으로는 도구 막대·버튼 높이를 빼지 못해 여전히 겹친다.
파일변경
view/QrFrameSize(새)한 변 길이 계산(시험 4개)
fragment/QrScanFragment레이아웃이 바뀔 때마다 placeFrame
layout/fragment_qr_scan네모·아래 안내 id

3코드 해설

int gap = gapBottom - gapTop;           // 도구 막대 아래 ~ 안내 위
int size = QrFrameSize.of(240dp, width, gap, 16dp);
lp.topMargin = gapTop + (gap - size) / 2;
frame.post(() -> frame.setLayoutParams(lp));
무엇을 화면 배치가 끝날 때마다(회전 포함) 빈 곳을 재서 네모 크기와 위치를 정한다.
왜 post 배치 콜백 안에서 바로 크기를 바꾸면 "배치 중에 다시 배치 요청" 경고가 난다. 다음 차례에 적용하고, 값이 같으면 아무것도 안 해 무한 반복을 막는다.
계산을 뺀 이유 크기 규칙(최대값·여백·0 아래로 안 감)을 Android 없이 단위 테스트로 지킬 수 있다.

6응용 실습

목표: 네모가 너무 작아지면(예: 120dp 미만) 안내 글자를 숨겨 네모 공간을 넓히기. 고칠 곳: 새 브랜치에서 placeFrame. 완료 기준: 아주 낮은 창(분할 화면)에서 네모가 120dp 이상.

힌트먼저 크기를 계산하고, 작으면 textQrHint를 GONE으로 바꾼다. 그러면 다시 배치가 일어나 빈 곳이 커진다.
정답 방향
boolean tiny = size < Math.round(120 * density);
if (tiny != (textHint.getVisibility() == View.GONE))
    textHint.setVisibility(tiny ? View.GONE : View.VISIBLE);
숨겼을 때도 다시 보이는 조건을 같은 값으로 계산해야 깜빡이지 않는다.
