ui-1 브랜치 · UI 1차 07e · D6(Keystore + 백업 제외, 평문 옮기고 지움) · UI-29 · 2026-11-24

1한눈에 보기

  • 암호화 보관: Wi-Fi 비밀번호를 평문 prefs(HomeAssistantPrefs.WIFI_PASSWORD)에서 꺼내 Keystore 키로 암호화해 새 prefs 파일 SecretPrefs에 둔다. 토큰 암호화 코드를 SecretStore로 일반화해 둘이 같이 쓴다(토큰 저장 위치는 그대로).
  • 옮기기: 앱을 켤 때 평문 값이 있으면 암호화 저장 → 디스크에 쓴 게 확인되면 평문 삭제. 실패하면 평문을 남겨 다음 실행에 다시 한다.
  • 백업 제외: 암호문은 이 기기의 키로만 풀리므로 SecretPrefs.xml을 자동 백업·기기 이전에서 뺐다(Android 11 이하·12 이상 파일 둘 다).
  • 설정 칸에 비밀번호를 다시 채우지 않고 "저장됨 · 바꿀 때만 입력" 힌트. 읽을 수 없으면(다른 기기 복원 등) 설정·기기 추가 화면이 다시 입력하라고 안내한다.

2흐름 그림 — 앱을 켤 때 옮기기

3코드 해설

① 지우기는 저장이 확실한 다음에

if (!plain.has()) return Outcome.NOTHING_TO_DO;
if (!encrypted.save(value)) return Outcome.KEPT_FOR_RETRY;
plain.remove();
return Outcome.MIGRATED;
왜 순서를 바꾸면(지우고 저장) 암호화가 실패한 순간 비밀번호가 사라져, 사용자가 다시 입력할 때까지 기기를 등록할 수 없다.
왜 commit() apply()는 디스크 쓰기를 나중에 해서, 서로 다른 prefs 파일 사이의 순서를 보장하지 않는다. 암호문 쓰기가 끝난 걸 확인하고 평문을 지우려고 commit()을 쓴다.
시험 Android Keystore는 단위 테스트에서 돌지 않으므로, 평문·암호화 저장소를 인터페이스로 받고 가짜(FakePlain, FakeTarget)로 시험한다.

② 일반화: 토큰 코드를 다시 쓴다

전
public final class TokenStore {
    private static final String KEY_ALIAS = "...token_key";
    private static final String PREF_KEY = "API_TOKEN_ENC";
    // 암호화 코드 60줄
}
후
private static final SecretStore STORE = new SecretStore(
        "HomeAssistantPrefs", "API_TOKEN_ENC", "home_assistant_api_token_key");
public static String load(Context c) { return STORE.load(c); }
주의 prefs 이름·키·별칭을 예전과 똑같이 넣어야 이미 저장된 토큰을 읽는다. 하나라도 바뀌면 업데이트한 사용자가 토큰을 잃는다.

③ 세 가지 상태

if (!stored) return NONE;          // 저장한 적 없음 → 비밀번호 없는 Wi-Fi("")
if (decrypted == null) return UNREADABLE;   // 다시 입력해야 함
return OK;

4용어 풀이

  • Android Keystore: 암호 키를 앱이 직접 볼 수 없게 시스템이 보관하는 곳. 키는 기기 밖으로 나가지 않는다.
  • AES-GCM: 암호화와 함께 변조 여부도 검사하는 방식. IV(매번 다른 시작값)를 암호문과 같이 저장한다.
  • 마이그레이션: 예전 저장 형식의 값을 새 형식으로 옮기는 일.
  • data_extraction_rules: Android 12 이상에서 클라우드 백업·기기 이전에 넣고 뺄 파일을 정하는 설정.

5이해도 질문

  1. 백업에서 SecretPrefs를 빼지 않으면 새 폰으로 복원했을 때 어떻게 되나?
  2. 옮기기가 실패한 상태에서 기기 등록을 하면 비밀번호는 어디서 오나?
정답 보기
  1. 암호문은 복원되지만 키가 없어 풀 수 없다(UNREADABLE). 빼 두면 처음부터 "저장한 적 없음"이라 안내가 분명하다.
  2. 남아 있는 평문에서 읽는다(WifiPasswordStore.read가 암호문이 없을 때 평문을 본다). 다음 실행에 옮겨지면 그때부터 암호문을 쓴다. 이 처리가 없으면 빈 비밀번호가 나가 등록이 실패한다.
