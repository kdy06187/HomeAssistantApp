  • 회전(U17): MainActivity가 회전 때 토큰 복호화·클라이언트 재생성을 되풀이하지 않는다.

2흐름 그림 — "다시 시도"가 돌아가는 길

3코드 해설

① 늦게 온 응답 막기

protected void onCleared() {
    cleared = true;
    if (commissionCall != null) commissionCall.cancel();
    pairingDevice = null;
    ...
}
public void onResponse(...) {
    if (cleared) return;
왜 Activity가 완전히 끝나도 OkHttp 요청은 계속 날아가고, 응답이 오면 콜백이 schedulePoll로 핸들러에 또 일을 넣었다. 이미 버린 ViewModel이 2초마다 서버에 묻는 "유령 폴링"이 된다.
취소만 하면? 취소 직전에 응답이 이미 메인 스레드 큐에 들어가 있을 수 있다. 그래서 플래그도 함께 본다.

② 진행 중일 때만 tick

before
public void run() {
    render();
    ticker.postDelayed(this, TICK_MS);
}
after
private void scheduleTick() {
    ticker.removeCallbacks(tick);
    if (started && status != null && status.isActive())
        ticker.postDelayed(tick, TICK_MS);
}
왜 결과 화면에도 매초 글자를 다시 써서 TalkBack이 같은 문장을 반복해 읽었다. 상태가 다시 진행 중이 되면 관찰자가 scheduleTick을 불러 다시 돈다.

③ 카메라: 푸는 순서

if (cameraProvider != null) cameraProvider.unbindAll();   // 먼저
if (analysisExecutor != null) analysisExecutor.shutdown(); // 나중
왜 실행기를 먼저 멈추면 아직 묶여 있는 분석기가 멈춘 실행기에 프레임을 넘기려다 거절 예외가 날 수 있다. 쓰는 쪽을 먼저 끊는다.

4용어 풀이

  • onCleared: ViewModel이 버려질 때 한 번 불린다(Activity가 회전이 아니라 진짜로 끝날 때).
  • onDestroyView: Fragment 객체는 살아 있지만 화면(View)만 버릴 때. 백스택에 가려진 Fragment가 여기 해당한다.
  • isStateSaved: 상태 저장이 끝나 화면 전환(트랜잭션)을 하면 안 되는 때.
  • 백스택 이름: addToBackStack("이름")으로 붙인 표. 그 지점까지 정확히 되돌릴 수 있다.

5이해도 질문

  1. 화면을 돌리면 DeviceViewModel.onCleared가 불릴까? 등록 폴링은?
  2. 홈 탭 → "등록 진행 보기"로 진행 화면만 연 뒤 "다시 시도"를 누르면 백스택은 어떻게 될까?
정답 보기
  1. 안 불린다. Activity 범위 ViewModel은 회전을 넘어 살아남으니 폴링도 계속된다.
  2. add_device가 없어 false → 진행 화면을 닫고 입력 화면을 새로 연다(스택: 홈 위에 입력 하나).

6응용 실습

목표: 기기 상세(DeviceDetailFragment.open)에도 백스택 이름을 붙여, 상세 위에서 무엇을 열었든 "상세로 돌아가기"를 한 번에 하게 만들기. 고칠 파일: DeviceDetailFragment(새 브랜치에서). 완료 기준: 이름 상수를 두고 popBackStackImmediate(이름, 0)가 true를 돌려준다.

힌트flags 0은 "그 항목은 남기고 위만 걷기", POP_BACK_STACK_INCLUSIVE는 "그 항목까지 걷기".
정답
public static final String BACK_STACK_NAME = "device_detail";
... .addToBackStack(BACK_STACK_NAME)
fm.popBackStackImmediate(DeviceDetailFragment.BACK_STACK_NAME, 0);
