APP-07f-3 해설 — 통신 실패를 기기 꺼짐으로 보지 않기

ui-1 브랜치 · UI 1차 07f · UI-31·32 · F-02(앱 문구) · 2026-11-24

1한눈에 보기

  • 통신 실패 ≠ 기기 꺼짐: 상태 조회(E5)가 서버에 닿지 못하면 예전엔 기기를 OFFLINE으로 바꿨다. 이제 마지막 확인값을 그대로 두고, 화면 위 배너가 "서버에 연결할 수 없어요"를 보인다(UI-32).
  • 영문 예외 문구 없음(F-02 앱 쪽): "unexpected end of stream" 같은 t.getMessage()를 화면에 쓰던 곳(목록, 삭제, 전력)을 모두 한글 문구로 바꿨다(UI-31). 테스트가 다시 생기지 않게 막는다.
  • 토스트 정리: 성공 "명령 성공!"과 진행 "기기 삭제 중..."을 없앴다(상태 칩이 결과를 보여 줌). 목록·전력 통신 실패 토스트도 배너가 대신한다. 삭제 성공(90일 안내)·삭제 실패 토스트는 남겼다.
  • 당겨서 새로고침 표시는 토스트 대신 새 신호 listRequestFinished로 끈다.
파일변경
viewmodel/DeviceViewModel.javaE5 실패 → 상태 유지, 예외 문구 제거, 토스트 정리, getListRequestFinished
HomeFragment·DeviceFragment새로고침 표시를 새 신호로 끔
NoRawErrorTextTest (새)소스에 t.getMessage()가 없고 E5 실패에 OFFLINE이 없는지

3코드 해설

전
public void onFailure(Call<DeviceStateResponse> call, Throwable t) {
    finishLoading(deviceId, "OFFLINE");
}
후
public void onFailure(Call<DeviceStateResponse> call, Throwable t) {
    // 서버에 닿지 못한 것이지 기기가 꺼진 것이 아니다.
    finishLoading(deviceId, null);   // null = 요청 전 상태로
}
왜 서버 PC가 꺼지면 모든 기기가 "오프라인"으로 바뀌어, 기기 문제로 오해하게 된다. 문제는 서버 연결이므로 배너 하나로 알린다.
전
showToast("통신 실패: " + t.getMessage());
// → "통신 실패: unexpected end of stream"
후
showToast("기기를 삭제하지 못했어요. " + ControlFailure.UNREACHABLE_SERVER);
F-02 틀린 토큰으로 POST하면 서버가 401 대신 연결을 끊어 OkHttp가 이 영문 예외를 낸다. 앱은 이제 한글 문구를 보이지만, "토큰 오류"가 아니라 "닿지 않음"으로 보이는 점은 서버가 401을 주도록 고쳐야 풀린다(서버 쪽 남은 문제).
