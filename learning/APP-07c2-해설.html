APP-07c-2 해설 — 상세 전력 15초 갱신

ui-1 브랜치 · UI 1차 07c · 결정 11(보이는 동안 15초), UI-12·UI-24 · 2026-11-24

1한눈에 보기

  • 새 카드: 전력 카드 = 현재 W(크게) · 누적 kWh · "마지막 갱신 09:05:07 · 15초마다".
  • 언제 묻나: Matter 기기 상세가 화면에 보이는 동안만(onStart~onStop) E6을 15초마다 묻는다. 다른 앱으로 가거나 뒤로 나가면 멈춘다.
  • 요청이 겹치지 않게: "15초마다 쏘기"가 아니라 "응답을 받은 뒤 15초 뒤에 다음 요청". 서버가 느려도 요청이 줄 서지 않는다.
  • 실패: 숫자는 이전 값 그대로 두고, 카드 위에 빨간 배너 "전력을 불러오지 못했어요. …" + "다시 시도". 카드를 흐리게 하거나 "로딩 중"으로 바꾸지 않는다(UI-12).
  • TCP_DIY 기기는 전력을 재지 않으므로(E6이 400) 카드도 숨기고 조회도 하지 않는다.

2흐름 그림 — 예약과 취소

3코드 해설

① 시간 계산은 Android 없는 클래스로

public long start(long now) {
    visible = true;
    if (inFlight) return NONE;          // 진행 중 요청이 끝나면 거기서 예약
    if (lastFinishedAt < 0) return 0L;  // 처음이면 바로
    return Math.max(0L, INTERVAL_MS - (now - lastFinishedAt));
}
왜 Handler·Retrofit이 섞이면 단위 테스트로 "회전하면 바로 다시 묻나?" 같은 것을 확인할 수 없다. 숫자만 다루는 EnergyPollSchedule로 떼어 내 7가지 경우를 테스트했다. 화면을 돌려 잠깐 onStop→onStart가 되어도 남은 시간만 기다리므로 요청이 몰리지 않는다.

② 예약은 ViewModel이 들고 있다

// Fragment
public void onStart() { started = true;  updatePolling(); }
public void onStop()  { started = false; updatePolling(); }
// ViewModel
mainHandler.postDelayed(detailPollTick, delay);
왜 요청 콜백이 Fragment를 직접 잡고 있으면 화면이 사라진 뒤 응답이 와서 죽은 뷰를 건드릴 수 있다. ViewModel은 화면 회전에도 살아 있고, 결과는 detailEnergy LiveData로만 내보낸다. Fragment는 "지금 보이나"만 알려 준다.

③ 홈과 같은 요청, 다른 실패 처리

private void requestEnergy(String deviceId, EnergyListener listener)
// 홈: onFailure → 토스트
// 상세: onFailure → EnergyReading.failure(…) → 배너
왜 성공했을 때 기기 값을 바꾸는 일(W·kWh·상태)은 같아야 홈 타일도 상세와 같은 숫자를 보인다. 실패를 알리는 방법만 화면마다 다르므로 그 부분만 리스너로 바꿔 끼운다. 15초마다 실패 토스트가 뜨면 화면이 시끄럽기 때문이다.

4용어 풀이

  • 폴링(polling): 서버가 알려 주지 않으니 앱이 일정 간격으로 직접 묻는 방식.
  • Handler.postDelayed: 메인 스레드에서 몇 ms 뒤에 Runnable을 실행하도록 예약. removeCallbacks로 취소.
  • accessibilityLiveRegion: 내용이 바뀌면 TalkBack이 읽어 주게 하는 표시. 실패 배너에 걸었다.

5이해도 질문

  2. 실패 배너가 떠도 "마지막 갱신" 시각이 바뀌지 않는 이유는?
정답 보기
  1. 약 35초(응답 20초 + 기다림 15초). 응답을 받은 뒤에 다음을 예약하므로 겹치지 않는다.
  2. 보이는 숫자는 마지막 성공 때의 값이다. EnergyReading.failure가 이전 성공 시각을 그대로 넘겨받아, 숫자와 시각이 같은 순간을 가리키게 한다.

6응용 실습

실습. 연속 실패면 간격 늘리기

  • 목표: 3번 연속 실패하면 다음 요청을 60초 뒤로 미루고, 한 번 성공하면 다시 15초로.
  • 고칠 파일: viewmodel/EnergyPollSchedule.java(finished(now, success)로 바꾸고 실패 횟수 세기), DeviceViewModel.scheduleNextDetailPoll, 테스트
  • 완료 기준: 테스트에서 실패 3번 → 60000, 그 뒤 성공 → 15000.
힌트실패 횟수는 reset()과 성공 때 0으로. "다시 시도" 버튼은 횟수와 상관없이 바로 묻는다(retryDetailEnergy는 그대로).
