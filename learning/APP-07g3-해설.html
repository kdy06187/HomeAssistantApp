APP-07g-3 해설 — 홈 타일 추이선

ui-1 브랜치 · UI 1차 07g · D14(최근 7일 일별) · 결정 53(기본 끔) · 2026-11-24

1한눈에 보기

  • 추이선을 켠 Matter 기기의 타일 아래에 작은 선(높이 32dp)이 생긴다. 축·글자·터치 없이 최근 7일 하루 사용량의 모양만 보여 준다.
  • 값은 07c-4의 E7 일별 집계(period=day, 오늘 포함 7일)를 그대로 쓴다.
  • 요청을 아끼는 규칙: 켠 기기만 묻고, 받은 값은 10분 동안 다시 묻지 않는다. 실패하면 1분 뒤에야 다시 묻는다. 같은 기기 요청이 진행 중이면 또 보내지 않는다.
  • 기록 없는 날은 선이 끊긴다. 7일 모두 기록이 없으면 선 대신 "–".
  • 선은 차트 라이브러리 없이 Canvas로 직접 그린다(타일마다 차트 객체를 만들면 무겁다).

2흐름 그림 — 홈 목록에서 선까지

3코드 해설

① 왜 캐시가 꼭 필요한가

viewModel.getDeviceList().observe(..., devices -> {
    ...
    viewModel.fetchTileTrends(trendDeviceIds(ordered, configs));
});
왜 홈 목록은 기기 하나의 상태·전력이 바뀔 때마다 다시 내보내진다(updateDevice). 캐시가 없으면 전력 응답이 올 때마다 E7이 또 나간다. TrendCache가 "진행 중·10분 안·실패 1분 안"이면 건너뛰게 해 실제 요청은 홈에 처음 들어올 때 정도로 줄어든다.

② 좌표 계산은 순수 함수

float x = n == 1 ? width / 2f : width * i / (n - 1);
float y = max == 0 ? height : height - height * value / max;
왜 화면 y는 아래로 갈수록 커지므로 큰 값일수록 위(작은 y)에 놓으려고 높이에서 뺀다. 값이 모두 0이면 0으로 나누지 않고 바닥에 납작한 선을 그린다. 기록 없는 날(null)에서 선을 끊어 여러 조각으로 나누고, 점 하나뿐인 조각은 동그라미로 그린다. 이 계산을 TrendValues에 두어 7가지 경우를 테스트했다.

③ 선 두께만큼 안쪽에

float inset = line.getStrokeWidth();
canvas.translate(getPaddingLeft() + inset, getPaddingTop() + inset);
왜 가장 큰 값은 y=0, 0은 y=높이에 그려진다. 두께가 있는 선을 가장자리에 그리면 절반이 잘린다. 두께만큼 안쪽 영역에서 계산한다.

4용어 풀이

  • 스파크라인(sparkline): 축·숫자 없이 흐름만 보이는 아주 작은 선 그래프.
  • Canvas·Path: 뷰의 onDraw에서 직접 그리는 도구. Path에 점을 이어 한 번에 그린다.
  • elapsedRealtime: 부팅 뒤 흐른 시간. 사용자가 시계를 바꿔도 거꾸로 가지 않아 캐시 시간 재기에 쓴다.
