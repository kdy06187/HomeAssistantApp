APP-07h-1 해설 — 비밀값 보관 보완

ui-1 브랜치 · UI 1차 보완 07h ① · U1·U6~U11·U28 · 2026-11-25

1한눈에 보기

  • 토큰도 SecretPrefs로(U28·U7): 토큰 암호문을 백업에 들어가는 HomeAssistantPrefs에서 백업 제외 SecretPrefs로 옮긴다. 키 별칭이 같아 암호문을 그대로 복사하고, 복사가 디스크에 써진 뒤에만 옛 칸을 지운다.
  • 상태 하나(U1): 토큰·Wi-Fi 비밀번호 모두 StoredSecret(없음 / 저장됨 / 읽을 수 없음). 첫 실행 = 토큰 없음. 읽을 수 없으면 "다시 입력해 주세요" 안내와 함께 토큰을 꼭 입력하게 한다(시작 탭·설정이 같은 기준).
  • 이전 규칙(U9): 새 저장소에 이미 값이 있으면 옛 값으로 덮지 않고 옛 값만 지운다. 빈 값은 옮기지 않고 "없음". 암호화가 실패하면 평문을 백업 제외 파일의 대기 칸으로 옮겨 둔다(U7).
  • 키 다시 만들기(U8): 암호화가 실패하면 그 칸의 Keystore 키를 지우고 한 번 다시 만든다.
  • 입력칸(U6): 토큰·Wi-Fi 비밀번호·페어링 코드 칸이 화면 상태 저장(Bundle)·자동완성에 들어가지 않게, 코드 칸은 키보드 추천 학습도 끈다.
  • QR 잔여값(U10): 기기 추가 화면을 새로 열 때·완전히 떠날 때 남은 스캔 값을 비운다.
  • 테스트 통과 표시(U11·U30·U22): 토큰 문자열을 들고 있지 않고 "입력 번호"만 비교한다. 테스트 중에 입력을 바꾸면(되돌려도) 통과로 치지 않는다. 저장은 토큰을 먼저 하고 실패하면 아무것도 바꾸지 않는다.

3코드 해설

if (target.has()) { legacy.remove(); return Outcome.DISCARDED_STALE; }
if (value == null || value.isEmpty()) { legacy.remove(); return Outcome.DISCARDED_EMPTY; }
if (!target.save(value)) return Outcome.KEPT_FOR_RETRY;
legacy.remove();
왜 "이미 있으면 덮지 않음" 평문 삭제(commit)가 실패해 옛 값이 남은 채로 사용자가 새 비밀번호를 저장했다면, 다음 실행의 이전이 새 값을 옛 값으로 덮는다. 새 칸이 있으면 그쪽이 최신이다.
if (encryptAndSave(context, value)) return true;
deleteKey();
return encryptAndSave(context, value);
왜 한 번만 키가 망가진 경우는 새 키로 풀리지만, 기기 문제라면 계속 실패한다. 한 번 다시 해 보고 안 되면 화면이 "저장하지 못했어요"를 보인다.

4용어 풀이

  • saveEnabled="false": 화면 회전·백그라운드 때 입력칸 글자를 상태 Bundle에 저장하지 않는다(비밀값이 디스크에 남지 않게).
  • textNoSuggestions: 키보드가 입력을 학습·추천하지 않게 한다.
