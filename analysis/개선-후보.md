## A. 실무 기본기 — 상용 수준이 되려면 먼저 갖춰야 할 것

새 기능보다 먼저 할 것들이다. 지금 앱은 "되긴 하는데 실패하면 이상해지는" 상태라서, 이것부터 해야 이후 기능이 안정적으로 쌓인다.

| ID | 항목 | 지금 | 상용 앱 수준 | 서버 | 난이도 | 연결 |
|---|---|---|---|---|---|---|
| A-1 | 제어 실패 처리 | 실패하면 `LOADING`에서 멈춤 | 누르면 바로 바뀐 것처럼 보여 주고(낙관적 UI), 실패하면 원래 상태로 되돌리며 이유를 알림. 요청 타임아웃 설정 | 불필요 | 하 | P-04, P-31, F-04 |
| A-2 | 실시간 상태 반영 | 화면에 들어오거나 버튼을 눌러야 갱신 | 다른 사람이 끄거나 기기가 꺼지면 바로 반영 (WebSocket 또는 SSE) | 필요 | 상 | F-02 |
| A-3 | 연결 상태·오류 화면 | 기기 관리 탭에서만 토스트 표시 | 상단에 "서버 연결 끊김" 배너 + 재시도, 빈 화면·오류 화면, 한 번만 보이는 이벤트 처리 | 불필요 | 중 | P-09, F-16 |
| A-4 | 서버 자동 찾기·연결 | IP·포트를 직접 입력, 틀리면 충돌 가능 | 같은 Wi-Fi에서 서버 자동 검색(mDNS/NSD) 또는 서버 화면의 QR 스캔, 저장 전 연결 테스트 | 일부(mDNS 광고) | 중 | P-01, P-07, F-14 |
| A-5 | 인증 | 누구나 API 호출 가능 | 처음 연결할 때 페어링 코드로 토큰 발급, 이후 요청에 토큰 첨부 | 필요 | 중 | P-03 |
| A-6 | 통신 암호화 | 평문 HTTP | HTTPS(자체 서명 인증서 고정) 또는 최소한 Wi-Fi 비밀번호 같은 민감 정보 암호화 | 필요 | 중 | P-03 |
| A-7 | 비밀 정보 저장 | Wi-Fi 비밀번호 평문 저장, 백업 포함 | Android Keystore 기반 암호화 저장, 백업 제외. SSID는 휴대폰의 현재 Wi-Fi에서 자동 입력 | 불필요 | 하 | P-02, F-15 |
| A-8 | 데이터 계층 정리 | ViewModel이 Retrofit을 직접 호출, 캐시 없음 | Repository 계층 + 로컬 DB(Room) 캐시 → 앱을 열면 마지막 상태가 즉시 보이고, 오프라인에서도 목록 표시 | 불필요 | 중 | P-10, P-14, P-29 |
| A-9 | 대시보드 설정 보존 | 위젯 삭제가 저장 안 됨, 휴대폰에만 저장 | 위젯 구성 저장, 서버에 백업해 다른 휴대폰·재설치 후에도 유지 | 일부 | 하~중 | P-11, P-28, P-30, F-11~F-13 |
| A-10 | 품질 기반 | 테스트 사실상 없음 | ViewModel 단위 테스트, 서버 응답 모의(MockWebServer) 테스트, CI 자동 빌드, 크래시 기록 | 불필요 | 중 | P-16, P-18 |

## B. 상용 앱 공통 기능 — 사용자가 "당연히 있겠지" 하는 것

| ID | 기능 | 설명 | 서버 | 난이도 | 비고 |
|---|---|---|---|---|---|
| B-1 | 방(공간)·즐겨찾기 | 거실/안방 등으로 기기 묶기, 자주 쓰는 기기 상단 고정 | 필요 | 중 | 기기가 늘어나면 필수 |
| B-2 | 기기 정보 편집 | 이름 변경, 방 지정, 아이콘, 드라이버 변경 | 필요 | 하 | 지금은 추가·삭제만 됨 |
| B-3 | 장면(Scene) | "외출"을 누르면 여러 기기를 한 번에 끄기 | 필요 | 중 | 실행은 서버에서 |
| B-4 | 자동화(루틴) | 시간 예약(예: 매일 23시 끄기), 조건(예: 대기전력 5W 미만 10분이면 끄기) | 필요 | 상 | 앱이 꺼져도 돌아야 하므로 서버가 실행 |
| B-5 | 알림 | 기기 오프라인, 전력 이상, 등록 완료/실패 | 필요 | 중 | 자체 호스팅이라 FCM 대신 앱의 실시간 연결(A-2)이나 ntfy 같은 자체 알림 고려 |
| B-6 | 활동 기록 | 누가·언제·무엇을 켜고 껐는지 | 필요 | 중 | 문제 추적에도 유용 |
| B-7 | 에너지 리포트 | 일/주/월 사용량, 기기별 비교, 전기요금 환산(누진 구간) | 일부(집계 API) | 중 | 지금은 실시간·누적 수치와 이력 차트뿐 |
| B-8 | 휴대폰 바깥 진입점 | 홈 화면 위젯, 빠른 설정 타일, Android 기기 제어(전원 버튼 메뉴, Device Controls API), 앱 바로가기 | 불필요 | 중 | 앱을 열지 않고 제어 → 실사용 만족도가 가장 크게 오름 |
| B-9 | 커미셔닝 UX | Matter QR 코드 카메라 스캔, 단계별 진행 표시(연결 중 → 등록 중 → 완료), 실패 원인 표시 | 일부 | 중 | 지금은 핀코드 직접 입력 + 임시 항목만 |
| B-10 | 외부(집 밖) 접속 | 집 밖에서도 제어 | 일부 | 중 | 포트 개방 대신 Tailscale/WireGuard 같은 VPN 안내가 안전. A-5·A-6 먼저 |
| B-11 | 여러 사용자·권한 | 가족 계정, 관리자/일반 권한 | 필요 | 상 | 인증(A-5) 이후 |
| B-12 | 다크 모드·접근성·다국어 | 문자열 리소스화, 글자 크기·스크린리더 대응 | 불필요 | 하 | P-19, P-20 |

## C. 차별화 — 직접 만든 서버라서 할 수 있는 것

상용 앱이 하기 어렵지만 이 프로젝트(아두이노 + Matter + 드라이버 구조)는 할 수 있는 것들이다. 포트폴리오에서 눈에 띄는 부분이 된다.

| ID | 기능 | 설명 | 서버 | 난이도 |
|---|---|---|---|---|
| C-1 | 기기 종류별 맞춤 화면(capability 기반) | 지금은 `Device.type`별로 위젯을 하드코딩함. 서버가 기기의 기능 목록(전원, 밝기, 센서 값, 전력 등)을 내려주면 앱이 그에 맞는 위젯을 자동 구성 → 새 기기 종류가 생겨도 앱 수정 최소화. Matter 클러스터 개념과 잘 맞음 | 필요 | 상 |
| C-2 | 드라이버 전용 제어 | PC 드라이버: Wake-on-LAN 켜기, 원격 종료·절전. TV 드라이버: 리모컨 화면(채널·음량·입력). 지금은 드라이버를 선택해 보내기만 함 | 필요 | 중 |
| C-3 | DIY 기기 진단 | 아두이노 기기의 마지막 응답 시각, 신호 세기(RSSI), 펌웨어 버전, 재연결 버튼 | 필요 | 중 |
| C-4 | 전력 기반 똑똑한 자동화 | "대기전력 차단", "세탁기 끝나면 알림"(전력이 일정 시간 0에 가까우면) | 필요 | 중 |
| C-5 | 개발자 모드 | 원본 패킷/응답 보기, 서버 로그 보기 → 디버깅과 학습에 유용 | 일부 | 하 |

## 추천 순서 (제안)

1. **안정화 묶음** — A-1, A-3, A-7, A-4(연결 테스트만이라도). 앱만 바꾸면 되고 난이도가 낮다. 문제점 '상' 다수가 여기서 해결된다.
2. **구조 정리** — A-8(Repository + 캐시), A-10(테스트). 이후 기능을 안전하게 붙이기 위한 바닥 공사.
3. **서버와 함께** — A-5(인증) → A-2(실시간) → B-2(기기 편집) → B-1(방). 서버 저장소와 API 계약을 같이 설계해야 한다.
4. **체감 기능** — B-8(홈 화면 위젯·기기 제어), B-7(에너지 리포트), C-2(드라이버 제어).
5. **확장** — B-3·B-4(장면·자동화), C-1(capability 기반), B-5(알림).

### 1단계에서 아직 정할 것

- 서버 작업 범위: 3번 묶음부터는 서버 저장소(HomeAssistantServer)도 함께 바꿔야 한다. 서버도 이 팀 구조(`projects/`)로 가져올지
- 기존 구조 유지(Java + XML) 또는 일부 재작성(Kotlin, Jetpack Compose 등) 여부
- 기한(과제 제출일·발표일 등)이 있는지 — 있으면 1~2번 묶음까지를 1차 목표로 자른다
