### 06a 구현 메모 (변경 목록과 다른 점)
- Java 필드·getter 이름(`id`, `type`, `getId()`, `getType()`)은 그대로 두고 JSON 키(`@SerializedName`)만 바꿨다. 화면 코드 수정을 줄이려고.
- `ApiError`는 `{"error":"문구"}`(문자열) 모양도 문구만 읽는다. v1.0 `{"result","message"}`는 읽지 않는다.
- F-03의 가짜 401 본문을 v2.0 모양(`UNAUTHORIZED`)으로 바꿨다.
- `AddDeviceResponse`는 빈 클래스로 남겼다(06e에서 jobId 응답으로 바뀜). 파일 삭제 없음.
- 아직 바꾸지 않은 것: OFF 뒤 50초 재확인(06b에서 202 `delaySeconds`로), E4가 `ControlResponse`를 반환형으로 쓰는 것(06c), `code`별 분기(06b·06c).
- `updateDevice`의 ID 비교도 null에 안전하게 바꿨다(`deviceId.equals(...)`).

### 06b~06d 구현 메모 (변경 목록과 다른 점)
- `PowerOffRecheck`는 이름을 그대로 두고 내용만 바꿨다(`delayMs(delaySeconds)`). `delaySeconds`가 없거나 음수면 45초로 보고 +5초.
- 202 토스트: "명령을 접수했습니다. 약 N초 뒤 꺼집니다/켜집니다."
- 404는 `DEVICE_NOT_FOUND`일 때만 "기기가 사라짐"으로 본다. 경로 404(`NOT_FOUND`)나 본문 없는 404는 일반 실패.
- E5·E6·E7 404는 토스트 없이 목록만 새로고침한다(자동 조회가 많아서). E2 404는 실패 토스트 + 새로고침.
- 삭제 성공 문구는 "90일 안에 다시 등록하면 기록을 이어받습니다"로 고정했다(`restorableUntil` 날짜 표시는 안 함).
- `unpaired`가 빠지거나 null이면 경고하지 않는다.
- E7 시각은 밀리초·`+00:00`을 받지 않는다(계약 그대로). 오면 라벨이 빈 문자열이 된다.
- 지운 파일·클래스 없음.
