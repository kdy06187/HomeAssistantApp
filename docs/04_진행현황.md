### 인수인계 (2026-11-24, 팀 세션 교대 → 07a 끝)
- 브랜치: `ui-1`(= `v2.0` + APP-07). push 안 함. `master`에 F-03, `v2.0`에 APP-06 전체.
- 07a·07b 끝, 07b 지울 목록 삭제함. 07g(타일 꾸미기)를 변경 목록에 추가함(D10~ 승인 대기). 다음 할 일: 총괄 승인 뒤 07c-1부터(순서 07c → 07g → 07d). 하위 단계마다 커밋 1개 + 학습 페이지, 지울 파일은 목록 먼저.
- 확인 방법: Gradle이 이 PC에서 안 돈다. javac(android-36 `android.jar` + Gradle 캐시 jar + `app/build` R.jar)로 main·test 컴파일 후 JUnit. **새 리소스는 옛 R.jar에 없으므로, `res/`를 읽어 앱 `R.java`를 새로 만들어 함께 컴파일한다**(라이브러리 R은 R.jar). 리소스 문법은 `build-tools/36.0.0/aapt2 compile --dir res`로 본다(링크는 안 함). 화면·카메라는 Studio 확인으로 따로 적는다.
- 커밋하지 않는 파일: `.idea/misc.xml`, `grep.exe.stackdump`(원래 있던 변경).
- 서버 13b·계약 14번 확정 뒤 06e(E3·E8)와 07d-3을 함께 다시 본다.

### 07a 구현 메모 (변경 목록과 다른 점)
- 색 토큰은 목업 값 그대로(M3 기준 색), 이름은 M3 역할(`color_surface`, `color_surface_container` …)을 따랐다. 보조·3차 색(`colorSecondary`·`colorTertiary`)도 강조색에 맞췄다(하단 탭 표시기가 기본 보라가 되지 않게).
- 다크 `themes.xml`은 색 연결을 복사하지 않고 `Platform.Theme.HomeAssistantApp`(상태 바 아이콘 밝기)만 다시 정의한다.
- 목록에 없던 것도 바꿨다: 벡터 아이콘 6개의 `android:tint`(검정 → `colorOnSurface`, 닫기 빨강 → `colorError`), CardView `cardBackgroundColor`, 차트 축 글자·격자 색(라이브러리 기본 검정이라 다크에서 안 보임). 차트 선 초록 → `colorPrimary`.
- 테스트 추가: `ColorTokensTest`(라이트·다크 이름 집합 + 글자/배경 15쌍 대비 4.5:1), `HardcodedStyleTest`(레이아웃·아이콘·Java의 색 값, 14sp 미만 글자 재발 방지).
- `DeviceStateLabel.Kind`가 `CONNECTED`에서 `ON`/`OFF`로 바뀌었다. 문구 "연결됨" → "켜짐"/"꺼짐", LOADING도 "확인 중…"을 보인다(예전엔 앞 문구 유지). LOADING 칩은 목업처럼 UNKNOWN과 같은 주황(WARNING)이고 문구·진행 표시로 구분한다. "페어링중"은 회색(OFF) 칩.
- `canToggle`은 만들었지만 아직 쓰지 않는다. 지금 위젯 스위치(`ToggleViewHolder`)는 07b에서 없어지므로 고치지 않았고, 07b 타일 스위치가 쓴다.
- 지울 후보(승인 전, 지우지 않음): `values/colors.xml`의 템플릿 색 `black`·`white`(어디서도 안 씀, 테스트에서 이름 비교 제외).

### 07b 구현 메모 (변경 목록과 다른 점)
- 아이콘 7개(홈·목록·추가·새로고침·삭제·순서 핸들·전원)는 기존 아이콘과 같은 24dp **Material Icons** 경로(Apache 2.0)로 넣었다(D9는 Material Symbols라고 적었지만 기존 파일과 모양을 맞춤). 타일 아이콘은 종류를 알 수 없어 모두 전원 아이콘.
- 홈은 `onStart`마다 `fetchDevices(true)`(E1 + Matter 기기 E6). 상태 E5는 기기 탭처럼 돌지 않는다. E6는 이제 LOADING을 거치지 않는다(타일 깜빡임 방지, 진행 중 요청이 있으면 상태는 안 건드림).
- 타일 전력: 켜짐일 때만 W 큰 숫자, 꺼짐·값 없음은 "–". 누적은 마지막 값. TCP_DIY는 전력 줄 없음. 오프라인은 "기기 응답 없음". 목업의 "지금 쓰는 전력" 요약 카드와 오프라인 점선 테두리는 목록에 없어서 넣지 않았다.
- 스위치 라벨은 "○○ 켜기"(목록대로). 타일 이름 부분 = 상세(07c 전까지 `DeviceDetailActivity`, 진입은 `DeviceDetailActivity.intentFor` 한 곳).
- 202(지연 수락)일 때는 06b대로 "켜는 중" 표시를 바로 풀고 안내 토스트를 띄운다.
- 제어 실패 Snackbar 대상: 409·502·500 등과 통신 실패. 401은 토큰 안내만, 404(기기 사라짐)는 예전대로 토스트 + 목록 새로고침. 문구 "‘이름’을/를 켜지 못했어요. (서버 문구)", 통신 실패는 "서버에 연결할 수 없어요."(영문 예외 문구 안 씀). 성공 토스트 "명령 성공!"은 07f에서 정리.
- 기기 추가 대화상자는 `AddDeviceDialog`로 옮겨 홈·기기 탭이 함께 쓴다(내용 그대로, 07d에서 전체 화면으로).
- 기기 탭: 길게 누르기 삭제를 없애고 삭제 버튼으로 대신했다. 대화상자 문구에서 "90일 복구"는 삭제 뒤 토스트에 그대로 있다. 목록 갱신이 null일 때 생기던 NPE 가능성도 막았다.
- `app CLAUDE.md`의 아키텍처 설명(대시보드 중첩 RecyclerView, "fetchDevices는 DeviceFragment에서만")이 이제 맞지 않는다. 지울 목록 승인 뒤 함께 고칠 것을 제안한다(이번엔 손대지 않음).

### 06a 구현 메모 (변경 목록과 다른 점)
- Java 필드·getter 이름(`id`, `type`, `getId()`, `getType()`)은 그대로 두고 JSON 키(`@SerializedName`)만 바꿨다. 화면 코드 수정을 줄이려고.
- `ApiError`는 `{"error":"문구"}`(문자열) 모양도 문구만 읽는다. v1.0 `{"result","message"}`는 읽지 않는다.
- F-03의 가짜 401 본문을 v2.0 모양(`UNAUTHORIZED`)으로 바꿨다.
- `AddDeviceResponse`는 빈 클래스로 남겼다(06e에서 jobId 응답으로 바뀜). 파일 삭제 없음.
- 아직 바꾸지 않은 것: OFF 뒤 50초 재확인(06b에서 202 `delaySeconds`로), E4가 `ControlResponse`를 반환형으로 쓰는 것(06c), `code`별 분기(06b·06c).
- `updateDevice`의 ID 비교도 null에 안전하게 바꿨다(`deviceId.equals(...)`).

### 06b~06d 구현 메모 (변경 목록과 다른 점)
- `PowerOffRecheck`는 이름을 그대로 두고 내용만 바꿨다(`delayMs(delaySeconds)`). `delaySeconds`가 없거나 음수면 45초로 보고 +5초.
- 202 토스트: "명령을 접수했습니다. 약 N초 뒤 꺼집니다/켜집니다."
- 404는 `DEVICE_NOT_FOUND`일 때만 "기기가 사라짐"으로 본다. 경로 404(`NOT_FOUND`)나 본문 없는 404는 일반 실패.
- E5·E6·E7 404는 토스트 없이 목록만 새로고침한다(자동 조회가 많아서). E2 404는 실패 토스트 + 새로고침.
- 삭제 성공 문구는 "90일 안에 다시 등록하면 기록을 이어받습니다"로 고정했다(`restorableUntil` 날짜 표시는 안 함).
- `unpaired`가 빠지거나 null이면 경고하지 않는다.
- E7 시각은 밀리초·`+00:00`을 받지 않는다(계약 그대로). 오면 라벨이 빈 문자열이 된다.
- 지운 파일·클래스 없음.

### 06e 구현 메모 (변경 목록과 다른 점)
- 폴링 중 404뿐 아니라 401도 멈추고 목록으로 확인한다(LOST). 500·통신 실패는 210초 전까지 다시 묻는다.
- 상한 판정: 다음 폴링이 210초를 넘으면 멈춘다. 성공·실패 응답은 상한을 넘었어도 그대로 처리한다.
- 202인데 `jobId`가 없으면 목록으로 확인하고 끝낸다.
- 목록을 새로 받아도 등록 중 임시 항목을 맨 위에 다시 붙인다(긴 등록 중 새로고침 대비).
- 이미 등록 중이면 `addDevice`가 "다른 기기 등록이 진행 중입니다"로 막는다(버튼 잠금과 이중).
- TCP_DIY 서버 IP는 앞뒤 공백을 지운다. Matter QR 내용은 그대로 보낸다.
- SSID·비밀번호 검사는 등록할 때와 설정 저장할 때 둘 다 한다.
